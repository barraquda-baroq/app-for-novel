# Claude 用コネクタ（Novel Studio 2.3〜。2.5 で相対比較、2.6 で資料、2.7 でカードをゴミ箱へ移す、2.8 でアイデア欄に書く、2.9 でアイデアのフォルダと複数のアカウント）

Claude（claude.ai・Claude のデスクトップアプリ・iPhone / Android の Claude アプリ）から Novel Studio の原稿を読み、
推敲案・改稿案・戦略メモ・作品批評・相対比較の分析・資料の記録・アイデアをアプリに足してもらうための仕組みです（リモート MCP サーバー）。
Cloudflare の無料プラン（Workers Free）に、あなた専用のコネクタを1つ置きます。

- Claude ができること: 「Claude に見せる」にしたタイトルの採用原稿・目次・設定・メモ・アイデア・戦略・作品批評を読む／本文を検索する／
  推敲案・改稿案・戦略メモ・批評プロンプト・批評の結果を**足す**／ホームの「相対比較」（比べるために読む既存の作品。2.5）の作品と分析を読む・分析を**足す**／ホームの「資料」（創作のために読む資料。主に買った書籍。2.6）の
  資料と記録を読む・記録を**足す**（資料のタグは読めるが付けない。タグは作者がアプリで付けて管理します）／作品相談のまとめなどを
  アイデア欄に新しいアイデアとして**足す**（2.8。「読む＋書き込む」のタイトルか、どのタイトルにも属さないホームのアイデアに。カードに
  「Claude が作成」の印が付きます）・Claude が足したアイデアの終わりに**追記**する（前の中身は消しません）・Claude が足したホームの
  アイデアを読む／アイデアを**フォルダ**（2段まで。2.9）に入れる（言われたフォルダが無ければ作る。作者がフォルダを言わない時は、書き込む前に
  「どのフォルダに入れますか」と候補を出して聞きます。Claude が作ったフォルダにも「Claude が作成」の印。ホームのフォルダは名前だけが見えます）／作者が頼んだ時だけ、Claude がコネクタで足した相対比較の分析・資料の記録・アイデアを、アプリの**ゴミ箱へ移す**
  （2.7。アイデアは 2.8 から。30日はアプリのゴミ箱から戻せます。「書き込みを許可」の時だけ）
- Claude ができないこと: 本文（稿）・全体戦略・応募計画の書き換え、作者が書いたアイデアへの追記、ゴミ箱へ移すこと以外の削除（作者が書いた・
  直したカード、作品・資料そのもの、ほかの種類の記録は移せません）、アイデアのフォルダの名前の変更・削除・移動とカードの移動（整理は作者が
  アプリでします。空のフォルダだけを作ることもしません）、見せていないタイトルを見ること、作者が書いたホームのアイデアを見ること、
  ゴミ箱・応募時の原稿の控えを見ること、端末で保存していない・まだ送っていない編集を見ること
- 足された記録は、アプリの 戦略（推敲案・改稿案・戦略メモ）と 作品批評、ホームの 相対比較・資料・アイデア欄（タイトルの「アイデア」にも）に、
  各端末が同期すると出ます。そこから先はふつうの記録としてチェック・編集・削除できます（全体戦略に足す・応募計画にする、はアプリのボタンで行います）
- コネクタを使わない時も、アプリの「Claude に頼む（手動）」でプロンプトと本文をコピーし、結果を貼り付けて同じことができます
  （アイデアを足す・追記する、ゴミ箱へ移すはコネクタだけ）

## 仕組み

```
claude.ai（Anthropic のクラウドから）
   │  MCP（https://novel-studio-connector.<サブドメイン>.workers.dev/mcp）・OAuth のトークン
   ▼
Cloudflare Worker「novel-studio-connector」（あなたのアカウント・無料プラン）
   ├ OAuth（claude.ai の公開の識別子だけを受け付ける。接続のたびに同意の画面）
   ├ MCP のツール（読む 14・足す 9・ゴミ箱へ移す 1）
   └ Vault（Durable Object）: コネクタ自身の匿名の Firebase アカウント（更新用トークンは暗号化）、持ち主の記録の写し、数の記録、
     接続ごとに読んだ話の指紋（推敲案の確認の範囲に使う。本文は持たない）
   ▼  匿名のアカウントの ID トークン
Firebase（novel-studio-3352e）: アクセスルールで「読む＋Claude の10の表・アイデアとそのフォルダ・2つの依頼の表に作るだけ」に絞られる
   ▲
Novel Studio（アプリ）: 連携の画面で、持ち主が許可する（config/connector。2.9 から接続の一覧。claude.ai で接続するごとに1つ。10まで）
```

- コネクタはあなたの Google アカウントのトークンを持ちません。持っているのは、アプリで許可した**匿名のアカウント**だけで、
  そのアカウントにできることはアクセスルール（`firestore.rules`）で「持ち主の記録を読む」「Claude の10の表（推敲案などの6つと、2.5 の
  相対比較の作品・その分析、2.6 の資料・その記録）と、2.7 のゴミ箱へ移す依頼（`trashRequests`。1件の JSON は 2,000 字まで）、2.8 の
  Claude のアイデア（`ideas`。id は `cy-…` だけ）とアイデアへの追記の依頼（`ideaAppends`。id は `cu-…` だけ。どちらも1件の JSON は 50,000 字まで）、
  2.9 の Claude のアイデアのフォルダ（`ideaFolders`。id は `cf-…` だけ。1件の JSON は 2,000 字まで）に新しく作る」に限られます（書き換え・削除・ゴミ箱の表と原稿の表への書き込み・バックアップからの復元の印は、ルールで拒まれます。アイデアの id の形を
  決めているので、コネクタが作者のアイデアと同じ id の記録を作ることも、作者のアイデアを書き換えることもできません。フォルダも同じく、作者の
  フォルダの名前を変える・移す・消すことも、カードを別のフォルダへ移すこともできません）。
- ゴミ箱へ移す時も、コネクタはカードを消しません。依頼を作るだけで、アプリが同期した時に、Claude が作ったカードか・作者が直していないか・1日100件を
  超えないかを確かめてから、作者の削除と同じ形でゴミ箱へ移します（それまでコネクタは、依頼の出ているカードを Claude に見せません）。
- アイデアに追記する時も、コネクタはカードを書き換えません。追記の依頼を作るだけで、アプリが同期した時に、Claude が作ったアイデアか・書き込める
  場所にあるかを確かめてから、カードの終わりに足します（Claude からは、依頼を送った直後から追記した後の中身が見えます）。
- 連携の許可は、claude.ai で「接続」を始めたブラウザと、あなたが Novel Studio にログインしているブラウザの両方がそろわないと完成しません
  （だれかが自分の接続のリンクをあなたに開かせても、連携はできません）。
- アプリの 設定 → Claude 連携 の［連携をすべて解除］で、その場で読めなくなります。［この接続を解除］（2.9）は、その claude.ai のアカウントの
  接続だけを止めます（次に使った時から。遅くとも1分ほどで。ほかの接続はそのまま）。どちらも、Firebase に繋がらない間・無料枠を使い切った間は
  例外があります（その間の答えと、すぐに切る方法は §2-E）。

## 1. 一度だけの準備

Windows（PowerShell）でも Mac（ターミナル）でも、手順とコマンドは同じです（コマンドは1行ずつ入力して Enter）。
2.4 の iPhone のアプリを作る時だけは Mac が要りますが（[MOBILE.md](MOBILE.md)）、コネクタの準備には要りません。

### 1-A. あなたが手で行うこと

1. **Node.js 24 LTS を入れる**（22 以上なら動きます）
   - Windows: <https://nodejs.org/ja> から 24 LTS のインストーラーを入れる。スタートメニューで「PowerShell」を開き、`node -v` が `v22` 以上なら OK。
     初めての時だけ `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` を実行し、確かめられたら `Y` を入力して Enter（npm のコマンドを動かせるようにする設定。
     管理者でなくてよい。docs/DEPLOY.md の手順 1 と同じ）。終わったら PowerShell を閉じて開き直す
   - Mac: 同じページから 24 LTS を入れる。「ターミナル」で `node -v` が `v22` 以上なら OK
2. **Cloudflare に登録する（無料・カード不要）**
   1. <https://dash.cloudflare.com/sign-up/workers-and-pages> で登録し、届いたメールの確認リンクを押す
   2. **アカウントを2段階認証で守る**（原稿を読む仕組みを置く場所なので必須）
      - 「Google でログイン」で登録した場合: Google アカウントの「2段階認証プロセス」がオンなら、Cloudflare へのログインも守られます。
        Cloudflare 自身の2段階認証も足したい時は、先にログイン画面の「Forgot password」で Cloudflare のパスワードを作ってから
        （Google で登録したアカウントにはパスワードが無く、そのままでは設定できません）、次の手順へ
      - メールアドレスとパスワードで登録した場合: 右上の人のアイコン →「My Profile」→「Authentication」→「Two-Factor Authentication」で、
        「Mobile App Authentication」（iPhone の「パスワード」アプリなどの確認コード）を設定し、表示されるリカバリーコードを安全な場所に保存する
   3. 左のメニューの「Workers & Pages」を開き、workers.dev のサブドメイン（例: `baroq`）を決める
      （コネクタの URL が `https://novel-studio-connector.baroq.workers.dev` になります）
3. **Firebase で匿名ログインを有効にする**
   1. [Firebase コンソール](https://console.firebase.google.com/project/novel-studio-3352e/authentication/providers) → novel-studio-3352e →
      「Authentication」→「ログイン方法」→「新しいプロバイダを追加」→「匿名」→ 有効にして「保存」
   2. コネクタ専用の身元に使います。何ができるかはアクセスルールで「読む＋Claude の記録を足す」だけに絞られています。
      「匿名のアカウントを自動で削除する」設定（Identity Platform の自動クリーンアップ）は有効にしないでください（連携が切れます）
4. **リポジトリを最新にして、部品を入れる**（PowerShell・ターミナルで1行ずつ）

   ```
   cd app-for-novel
   git pull
   npm ci
   npm --prefix connector ci
   ```

   Firebase にまだログインしていなければ `npx firebase login` も（docs/DEPLOY.md の手順 1）。
5. **準備のスクリプトを動かす**

   ```
   npm run connector:setup
   ```

   Cloudflare にログインしていなければブラウザが開くので、ログインして「Allow」を押します。最後に
   `claude.ai に登録する URL: https://novel-studio-connector.<サブドメイン>.workers.dev/mcp` と出れば完了です（この URL は秘密ではありません）。
   「匿名ログインが無効です」と出たら、手順 3 をやり直して、もう一度 `npm run connector:setup` を実行します。
6. **すべての端末のアプリを 2.3 にする**: Windows（Edge のアプリ）・iPhone・Android で「新しいバージョンのアプリがあります」→［更新する］を押し、
   設定 → 同期 が「同期済み」になるまで待つ（2.3 では初回だけ全件を受け取り直します）。
   古い版のアプリで「バックアップから復元」「すべて削除」をすると、Claude の記録が消えるので、先にすべての端末を更新してください。
7. **claude.ai にコネクタを登録する**（パソコンのブラウザで。スマホのアプリからは登録できません）
   1. claude.ai →「カスタマイズ」→「コネクタ」→「+ 追加」→「カスタムコネクタを追加」
   2. 名前 `Novel Studio`、URL は手順 5 の `…/mcp`（アプリの 設定 → Claude 連携 からもコピーできます）→「続行」
   3. 認証:「今すぐサインイン」
   4. OAuth クライアント:「Claudeの公開されたアイデンティティを使用（推奨）」
   5. リクエストヘッダー: 空のまま →「追加」
8. **Novel Studio で許可する**
   1. 開いた「Novel Studio コネクタ」の画面で［Novel Studio で確認する］を押す
   2. Novel Studio の画面が開く（ログインしていなければ Google でログイン。そのブラウザもふつうの同期する端末になります）
   3. Claude に見せるタイトルを選び（「見せない／読むだけ／読む＋書き込む」）、「推敲案などの書き込みも許可」を確かめて［許可する］
      （2.9 からは「この接続」の名前（既定は「接続1」「接続2」…）も決められます。複数のアカウントで使う時は §2-E）
   4. claude.ai に戻り、「接続済み」になれば完了
9. **ツールの許可を決める**: 「カスタマイズ → コネクタ → Novel Studio」のツールの権限で、読む系（〜を見る・〜を読む・検索）は「常に許可」、
   足す系（推敲案を追加 など）は最初は「承認が必要」がおすすめです。足す系は本文を書き換えないので、慣れたら「常に許可」でも構いません。
   「アイデアを足す」「アイデアに追記」（2.8）は「常に許可」で構いません（何も消さず、前の中身も残ります）。
   「カードをゴミ箱へ移す」（2.7）は、いつも「承認が必要」のままにしてください（移す前に、どのカードを移すかを claude.ai の確認で見られます）。
   リサーチモードでは確認なしにツールが呼ばれるので、そのチャットではコネクタをオフにしてください（権限の表示名は画面と少し違うことがあります）。
10. **iPhone・Android の Claude アプリ**: 同じアカウントならそのまま使えます。チャットの「＋」→「コネクタ」で Novel Studio をオンにします。

### 1-B. `npm run connector:setup` が自動で行うこと

1. Cloudflare にログインしているかを確かめる（していなければ `wrangler login` でブラウザを開く）
2. コネクタを公開する（`wrangler deploy`。OAuth 用の KV と Vault の Durable Object も自動で作られる）
3. 公開した URL を `connector.local.json`（リポジトリの直下。Git には入らない）に書き、URL を渡して公開し直す
4. 鍵 `TOKEN_ENC_KEY`（32バイトの乱数）を作り、**画面に出さずに** `wrangler secret put` に渡す（もう設定されていれば、そのまま使う）
5. コネクタを確かめる（`npm run connector:check` と同じ。Firebase の匿名ログインが無効ならここで止まって直し方を出す）
6. アプリとアクセスルールを公開する（`npm run deploy` と同じ。コネクタの URL がアプリに入る）
7. claude.ai に登録する URL を出す

どの手順でも、秘密（鍵・トークン）を入力・コピーすることはありません。

## 2. 試す

claude.ai のチャットで（Novel Studio のコネクタをオンにして）:

- 「Novel Studio のタイトル一覧を見せて」
- 「『星の庭』の目次と文字数を見せて」
- 「第1話を読んで、ら抜き・誤字脱字・既成表現の推敲案を追加して」→ アプリの 戦略 → 推敲案 に数秒〜数十秒で出ます
- 「全体を通して、構成と人物の批評をして、作品批評に記録して」
- 「この作品で狙えるコンテストを3つ挙げて、戦略メモに追加して」→ 戦略 → 戦略メモ の［応募計画にする］で応募計画に

- 「プロジェクトの PDF『銀河の果ての図書館』を構成・文体・人物・冒頭の掴みの観点で分析して、相対比較に追加して」→ ホームの 相対比較 に
  作品（まだ相対比較に無ければ作品も）と観点ごとの分析が出ます（PDF を claude.ai のプロジェクトに置いて、そのプロジェクトのチャットで頼みます。§2-A）
- 「『星の庭』を、相対比較する作品と比べながら批評して、作品批評に記録して」→ Claude が相対比較する作品の分析を読み（PDF は読み直さない）、
  結果に「比べた作品」が付きます（相対比較する作品は、アプリのタイトルの 作品批評 →「相対比較する作品」で選びます）
- Claude には「ベンチ作品」「比較作品」と言っても通じます（サーバーの説明と分析を追加するツールの説明に、同じものだと書いてあります）
- 「プロジェクトの PDF『現代の特殊部隊』を資料として読み、要約・創作に役立つ知識・描写に使える部分・サンプルシーンを資料に追加して」→ ホームの 資料 に
  資料（まだ資料の棚に無ければ資料も）と項目ごとの記録が出ます（PDF を claude.ai のプロジェクトに置いて、そのプロジェクトのチャットで頼みます。§2-C）。
  タグ（ミリタリ・現代・戦闘など）は、その後にアプリで自分で付けます
- 「資料のうち、タグ「ミリタリ」と「現代」が付いたものの記録を読んで、第3話の突入の場面の描写を直す案を改稿案に追加して」→ Claude が資料の一覧を
  タグで絞り（`novel_list_materials` の `tags`）、記録を読んで（`novel_get_material`）使います。Claude には「参考資料」「資料本」と言っても通じます

大きなタイトル（数十万字）は、Claude が 2万字ずつ（多い時は6万字ずつ）読み進めます。推敲は範囲を区切って何回かに分けると確実です
（推敲案の一覧に「未確認 #41〜#300」のように残りの範囲が出ます）。
Claude が話を読んだ後、推敲案を足す前に、アプリでその話を直して保存した時は、その話は確認済みにならず「本文が変わった話 #3」として残ります
（Claude の答えにも「補足: #3 第3話 は読んだ後に本文が変わっています…」と出ます。直した所は推敲されていないので、その話をもう一度頼みます）。

批評の結果・批評プロンプト・改稿案・戦略メモの文章の長さに上限はありません。ただしコネクタが書く記録は1件を JSON にして 200,000 字まで
（コネクタは分割文書を書かないため。アクセスルールも同じ値）で、それを超える長い批評の結果などは、コネクタが「何件に分ければよいか」を答え、
Claude が前半・後半のように分けて、各部の1行目の先頭に「（1/2）」「（2/2）」と番号を付けて記録します（アプリと Claude の一覧では番号の順に並びます。
1行目の途中の「（7/12）」などは番号と見なしません。戦略メモは見出しの末尾の「（1/2）」も番号です。以前の版で1行目の見出しの末尾に
番号を付けて記録した結果・分析（「# 批評（1/2）」）は、番号の順にまとめず新しい順に並びます）。
相対比較の分析・資料の記録を分ける時は、1つの分析の部をすべて同じ呼び出しで送ります（コネクタの答えもそう伝えます。別々の呼び出しで送ると、
同じ日に同じ作品・観点の分析を送ったほかのチャット・アカウントの部と混ざって並ぶことがあるため）。
アプリの「結果を貼り付け」には、この上限もありません（端末が分割して同期します）。長い批評の結果は、閉じている間は最初の部分だけを表示し、
［全文を表示］で少しずつ最後まで出します（数十万字の結果でも画面が止まらないように）。
上限があるのは短い項目だけです（推敲案の引用 100字・直前の文字 30字・種類の名前 20字・直し方 500字・理由 300字、見出し・名前 60〜80字、
URL 2,000字、推敲案は1回100件など）。

### 2-A. 既存の作品の PDF を claude.ai のプロジェクトに置いて、相対比較の作品として分析してもらう

個人的に購入した既存の作品の PDF は、Novel Studio には置きません（Firebase の無料プランにはファイルの置き場所が無く、原稿と違って
何度も読み直すものでもないため）。PDF は claude.ai の**プロジェクト**のナレッジに置いたままにして、Claude が分析した内容だけを
Novel Studio のホームの「相対比較」に残します。後で作品批評をする時は、Claude はその分析を読むので、PDF を毎回渡さなくて済みます。

1. claude.ai で「プロジェクト」を作り（例: 「相対比較」）、ナレッジに作品の PDF を追加します（作品ごとにプロジェクトを分けても、
   1つにまとめても構いません）。
2. プロジェクトの設定（または、チャットの入力欄の「＋」→ コネクタ）で Novel Studio のコネクタをオンにします。
3. プロジェクトの中で新しいチャットを開き、たとえば次のように頼みます。
   - 「プロジェクトの PDF『銀河の果ての図書館』を構成・文体・人物・冒頭の掴みの観点で分析して、相対比較に追加して」
   Claude は `novel_list_bench_works` で相対比較の作品を確かめ、まだ無い作品なら作品名・著者を付けて（`new_work`）、観点ごとの分析を
   `novel_add_bench_analysis` で足します（承認の画面に「相対比較に分析を追加」と出ます）。同じ内容を2回足しても増えません。
   足した答えには、新しく作った作品も既にある作品も、いつも `w:…『作品名』（著者）` が出ます（続けて同じ作品に足す時は、その `w:…` で指せます）。
   自分の原稿を何回も分析してもらう時は、作品名を「【原稿】原稿名（第2稿・2回目）」のように「【原稿】」で始め、最後の括弧を回ごとに変えます
   （同じ作品名だと前の回の作品に足されます。Claude にもツールの説明でそう伝えてあり、前の回を一覧で確かめて違う回の札にします。
   一覧は作品名で絞れます（部分一致）。「【原稿】原稿名（」を含み「【対照】」を含まない作品に絞ると、その原稿の回だけを確かめられます）。
   アプリはこの名前の作品を原稿ごとに1枚にまとめ、開くと新しい回から並べます。
4. アプリのホームの「相対比較」に作品が出ます。作品の画面で、観点ごとの分析を読む・直す・削除する、PDF の置き場所（プロジェクトの名前）を
   メモしておく、ができます。
   作品の画面の「ジャンル」で作品にタグを付けられます（2.7）。観点「14 検索用タグ」の「- 判定したジャンル：」「- ジャンル／サブジャンル：」の行の
   ジャンルは、アプリが同期の後に自動で付けます（Claude はタグを書けません）。作者が外したタグは、新しい 14 が来るまで付き直しません。
   Claude は `novel_list_bench_works` の `tags`（例: `tags: ["恋愛"]`。いくつか渡すと、すべて持つ作品だけ）でタグの付いた作品に絞れ、
   一覧の最初の行「タグ（作品の数）: …」で棚で使っているタグを確かめられます。アプリがまだ付けていない 14 のタグも、一覧と絞り込みには出ます。
5. 比べたいタイトルの 作品批評 →「相対比較する作品」で作品を選ぶと、批評の依頼（「Claude 用にコピー」・コネクタの `novel_get_critique`）に
   相対比較する作品が入り、Claude は `novel_get_bench_analysis` で分析を読んで比べます。

コネクタを使わない時は、作品の画面の「Claude に頼む（手動）」で依頼文をコピーしてプロジェクトのチャットに貼り、答えを「結果を貼り付け」で取り込みます。
相対比較の作品と分析はどのタイトルにも属さない覚え書きなので、タイトルの「Claude に見せる」とは関係なく、連携したコネクタにはいつも見えます
（足すのは「書き込みを許可」の時だけ）。

### 2-C. 資料の PDF を claude.ai のプロジェクトに置いて、資料の記録を書いてもらう（2.6）

創作のために買った本（主に書籍）の PDF も、相対比較と同じく Novel Studio には置かず、claude.ai の**プロジェクト**のナレッジに置いたままにして、
Claude が読んでまとめた記録だけを Novel Studio のホームの「資料」に残します。後で設定や描写を考える時は、Claude はその記録を読むので、
PDF を毎回渡さなくて済みます。

1. claude.ai で「プロジェクト」を作り（例: 「資料」）、ナレッジに資料の PDF を追加します（資料ごとにプロジェクトを分けても、1つにまとめても構いません）。
2. プロジェクトの設定（または、チャットの入力欄の「＋」→ コネクタ）で Novel Studio のコネクタをオンにします。
3. プロジェクトの中で新しいチャットを開き、たとえば次のように頼みます。
   - 「プロジェクトの PDF『現代の特殊部隊』を資料として読み、要約・創作に役立つ知識・描写に使える部分・サンプルシーンを資料に追加して」
   Claude は `novel_list_materials` で資料の棚を確かめ、まだ無い資料なら資料名・著者を付けて（`new_material`）、項目ごとの記録を
   `novel_add_material_notes` で足します（承認の画面に「資料に記録を追加」と出ます）。決まった項目は4つで、アプリはこの順に並べます:
   「要約」（資料の全体の要約。章立てに沿って）、「創作に役立つ知識」（設定・展開・人物に使えそうな知識・事実・数字・用語を、資料の中から**すべて**。
   出どころつき）、「描写に使える部分」（五感・道具・手順・場所・時代の空気など、描写に使えそうな具体的な部分を**すべて**。出どころつき）、
   「サンプルシーン」（拾った知識と描写で仮想の場面を1つ立ち上げた短いサンプル）。ほかの名前の項目（「用語集」「年表」など）も頼めます。
   長い時は項目ごとに分けて送ります。同じ内容を2回足しても増えません。足した答えには、新しく作った資料も既にある資料も、いつも
   `d:…『資料名』（著者）` が出ます（続けて同じ資料に足す時は、その `d:…` で指せます）。資料名が同じでも著者が違えば別の資料になります。
4. アプリのホームの「資料」に資料が出ます。**タグはここで自分で付けます**（資料の画面の「タグを付ける」、または「資料の情報を直す」。Claude はタグを
   付けません）。たとえば『現代の特殊部隊』に「ミリタリ」「現代」「戦闘」。棚の上のタグのチップを押すと、そのタグの資料だけに絞れ、いくつか選ぶと
   選んだタグをすべて持つ資料だけになります。検索の欄（資料名・著者・タグ・メモ）でも探せます。「タグを管理」でタグの名前を変える・削除する
   （すべての資料で）ができます。資料の画面では、項目ごとの記録を読む・直す・削除する、PDF の置き場所（プロジェクトの名前）をメモしておく、ができます。
5. 付けたタグは Claude にも見えるので、「タグ「ミリタリ」の資料を使って…」のように頼むと、Claude は `novel_list_materials` の `tags` で絞って
   （タグの名前そのもので照らします。いくつか渡すと、すべてを持つ資料だけ）、`novel_get_material` で記録を読みます。

コネクタを使わない時は、資料の画面の「Claude に頼む（手動）」で依頼文をコピーしてプロジェクトのチャットに貼り、答えを「結果を貼り付け」で取り込みます。
資料とその記録もどのタイトルにも属さない覚え書きなので、タイトルの「Claude に見せる」とは関係なく、連携したコネクタにはいつも見えます
（足すのは「書き込みを許可」の時だけ）。

### 2-D. 作品相談のまとめをアイデア欄に書いてもらう（2.8）

claude.ai で作品の相談をした後、まとめを Novel Studio のアイデア欄に直接書いてもらえます（コピーして貼り付けなくて済みます）。

1. 相談の最後に、たとえば次のように頼みます。
   - 「今日のまとめを『星の庭』のアイデアに足して。名前は『第3章の動機』」（タイトルを言うと、そのタイトルのアイデアに入ります。
     タイトルの「Claude に見せる」が「読む＋書き込む」の時だけ）
   - 「新作の案として、ホームのアイデアに足して」（タイトルを言わないと、どのタイトルにも属さないホームのアイデアに入ります）
   Claude は `novel_add_ideas` で足し、答えで入れた場所（タイトル『…』のアイデアか、ホームのアイデア）とアイデアの `i:…` を伝えます
   （2.9 からは、フォルダを言わないと先に「どのフォルダに入れますか」と聞かれます。6）。
2. カードの1行目は、コネクタが付ける作った日付と時刻（日本時間）です。名前を言った時だけ、同じ行の後ろに付きます（「2026/11/12 14:32　第3章の動機」）。
   2行目からが中身です。カードは Markdown を変換せずにそのまま出すので、Claude は「・」の箇条書きと【】の小見出しで書きます（Markdown の記号が
   あると足さずに書き直します）。足したアイデアは、その場所の済みでないアイデアの先頭に並び、「Claude が作成」の印が付きます。
3. 同じチャットで続けて相談した時は、「さっきのアイデアに今日の変更を追記して」と頼めます。Claude は先に `novel_get_notes` で今の中身を読み
   （アプリで直した所も踏まえるため）、`novel_append_to_idea` でカードの終わりに、空行を置いて「2026/11/12のセッションで以下の内容へ変更」の行と
   新しい内容を足します。前の中身・あなたが直した所は消えず、並びの位置と「済み」も変わりません。追記は依頼として送られ、アプリを開いて同期した時に
   カードに足されます（Claude からは、送った直後から追記した後の中身が見えます）。追記できるのは、Claude がコネクタで作ったアイデアだけです。
4. 要らなくなった Claude のアイデアは、アプリで削除するか、Claude に「そのアイデアをゴミ箱へ移して」と頼みます（`novel_move_cards_to_trash`。
   アプリで直したアイデアは Claude からは移せません。Claude の追記だけなら移せます）。
5. Claude が読めるホームのアイデアは、Claude が作ったものだけです（あなたが書いたホームのアイデアは、今までどおり Claude から見えません）。
6. **フォルダに入れる（2.9）**: アイデアはフォルダ（2段まで）に入れられます。頼む時にフォルダを言うと、そこに入ります。
   - 「今日のまとめを新作の相談に入れて」（1段目だけ）→ 1段目「新作の相談」（無ければ作る）の中に、2段目「2026/11/12　港町の新作」（日付はコネクタが
     付け、相談のテーマは Claude が短く付けます。名前を言えばその名前）を作って、まとめて入れます。同じ日に同じテーマで続けて足すと、同じ2段目に入ります。
   - 「場面の相談の『雨の駅』に入れて」（2段とも）→ そのフォルダに入れます（無ければ作る）。
   - フォルダの名前は、字の幅・空白の違いを同じと見なして探します（全角と半角の「雨の駅２」「雨の駅2」、空白の「港町　新作」「港町 新作」は同じ。空白の有る無しは別）。1段目に無く、2段目に同じ名前が1つだけ
     あれば、その2段目に入れます。同じ名前が2つ以上ある時は、Claude が `f:…` で選び直します（1段目だけを言った時は、テーマも付けて選び直し、
     その中に2段目「2026/11/12　テーマ」を作ります）。
   - フォルダを言わなかった時は、Claude は書き込む前に「どのフォルダに入れますか」と、今のフォルダの名前を出して聞きます。フォルダの名前を答えるか、
     「任せる」（1件ならフォルダの外、2件以上なら新しい1段目「2026/11/12　テーマ」にまとめる）、「フォルダに入れないで」と答えます。
   - 答えにフォルダの名前と `f:…` が出ます。同じ相談で続けて足す時は、Claude はその `f:…` だけを渡して、同じフォルダにじかに入れます（「任せる」で
     作った1段目にも入ります。1段目の `f:…` にテーマを付けた時だけ、その中に2段目「2026/11/12　テーマ」を作ります）。
   - 2台で同じ時にフォルダを移した（移したフォルダの中にフォルダを作った・移した先のフォルダを消した）ために、1段目に見えても記録では別のフォルダの
     中にあるフォルダには、Claude は中に新しいフォルダを作れません。そのフォルダを言われた時は、Claude はそこにじかに入れ、答えの補足でそう伝えます
     （中にもう見えているフォルダを言われた時は、そこに入れます）。アプリでそのフォルダの［…］→「移動…」から「1段目にする」を選ぶと直ります
     （中にフォルダを作っても直ります）。
   - Claude が作ったフォルダにも「Claude が作成」の印が付きます。Claude はカードを足す時だけフォルダを作り（空のフォルダは作りません）、フォルダの名前の
     変更・並べ替え・移動・削除とカードの出し入れはできません（アプリであなたがします）。
   - Claude には、ホームのフォルダの名前（あなたが作ったものも）と、見せているタイトルのフォルダの名前が見えます（あなたが書いたホームのカードの中身は
     見えません）。
7. 2.9 に更新した後は、claude.ai で**新しいチャット**を始めてください（前のチャットはフォルダの入力の無い前のツールの形を覚えていて、コネクタは
   フォルダの決まっていない呼び出しを断ります）。

### 2-E. 複数の claude.ai のアカウントから使う（2.9）

- 別のアカウントでは、そのアカウントの claude.ai で §1-A の 7〜9 を行います（コネクタを登録し、アプリで名前を決めて許可し、ツールの権限も
  アカウントごとに決めます。「カードをゴミ箱へ移す」は「承認が必要」に）。「接続」は、そのアカウントの claude.ai を開いているブラウザ（別の
  プロフィールなど）で最後まで行い、そこで開いた Novel Studio には**持ち主の Google アカウント**でログインします（そのアカウントの Google ではなく。
  §5 の「持ち主ではありません」「別のブラウザ」）。そのブラウザもふつうの同期する端末になります。
- 1つの Novel Studio に、claude.ai のアカウントを同時に10まで接続できます。別のアカウントで接続しても、前の接続は切れません（2.8 までは切れていました）。
- 接続するたびに、アプリの許可の画面の「この接続」で名前を付けます（既定は空いている一番小さい番号の「接続1」「接続2」…。20字まで。同じ名前は
  付けられません。既定の名前のまま許可して、その間にほかの端末で同じ名前の接続が足されていた時は、空いている番号になります）。あとから
  設定 → Claude 連携 の［名前を変える］で変えられます。「仕事用」「個人」のように、どのアカウントか分かる名前にしておくと便利です。
- どの名前が claude.ai のどのアカウントかは、アプリからは分かりません。そのアカウントの Claude に「Novel Studio の状態（novel_status）を見て」と頼むと、
  最後の行に「この接続: 接続2（接続 3 / 10。…）」と出ます。`novel_status` の「連携: 済み（…）」は、そのアカウントの接続を許可した日時です（設定 →
  Claude 連携 の一覧の「許可した日時」と同じ）。
- 同じアカウントで接続し直した時も、新しい接続として足されます（どれが同じアカウントか分からないため）。許可の画面で「○○と入れ替える」を選ぶと、
  前の接続を外して入れ替えます（前の接続はすぐ使えなくなります）。claude.ai で接続がうまくいかずにやり直している時は、15分以内に許可した接続があれば
  許可の画面が入れ替えを勧めます（使わない接続が一覧に残らないように）。
- **別のアカウントを続けて接続する時**（相対比較のアカウントの次に推敲のアカウント、など）も、15分以内なら「15分以内に許可した「接続1」があります。…」と
  出ますが、「新しい接続として足す」のまま許可してください（画面にもそう出ます）。入れ替えると前のアカウントがすぐ使えなくなり、一覧には前の名前のまま
  1つだけ残るので気づきにくくなります（間違えた時は、前のアカウントの claude.ai で接続し直します）。迷った時も「新しい接続として足す」で構いません
  （使わない接続が残っても10のうち1つを使うだけで、あとから［この接続を解除］で外せます）。
- 10ある時は、入れ替える接続を選ぶか、許可の画面の「いまの接続」の一覧で1つ［この接続を解除］してから［許可する］を押します（15分以内に許可した
  接続があれば、それが入れ替える先に選んであります。無ければ「選んでください」のままで、選ぶまで押せません）。選んだ入れ替える先を一覧で解除すると、
  ほかの接続を代わりに選ぶことはせず、「新しい接続として足す」に戻ります。
- 設定 → Claude 連携 の［この接続を解除］は、その接続だけを止めます（次に使った時から、遅くとも1分ほどで「Novel Studio 側で連携が解除されています」。
  ほかの接続はそのまま。一覧が1つの時は「最後の接続です。連携をすべて解除しますか？」と確かめますが、その間にほかの端末で足された接続があれば、
  それは残ります）。そのアカウントでまた使う時は、claude.ai で接続し直します（新しい接続として足されます）。［連携をすべて解除］はすべての接続を
  その場で止めます（下の例外も同じ）。
- Firebase に繋がらない間や、Firebase の無料枠を使い切った間は、解除した接続（［連携をすべて解除］の後は、どの接続も）でも前に取り込んだ内容を
  読めることがあります（書き込みはできません。コネクタが記録を読み直せた時に止まります）。すぐに切るには、そのアカウントの claude.ai でもその接続を
  外してください（§4 の「claude.ai から外す」。すべて解除した時は、使っていたどのアカウントでも）。
- 2.8 までの接続は、2.9 にしても繋ぎ直さずに使え、一覧に「接続1」と出ます。2.8 までに claude.ai と Claude Code の両方で接続していた時は、どちらも
  「接続1」で、接続1 を解除すると両方とも止まります。2.8 で別のアカウントを接続した時に切れた接続は、もう取り消されているので、そのアカウントで
  claude.ai から接続し直してください（新しい接続として足されます）。

**設定はすべての接続に共通**

- 「書き込みを許可」は1つで、すべての接続に効きます。許可の画面で「推敲案などの書き込みも許可」に触らなければ、いまの設定のままです（いまの接続の
  一覧を読めなかった時は、分からないことを示す形で出ます）。ただし、コネクタを用意し直した後（前の接続が使えなくなっている時）は新しく始める
  連携なので、触らなければ許可になります。オフからオンに戻した時は、どの接続も数秒で書けるようになります（「書き込みは停止中です」と断る前に、
  5秒より前に読んだ設定なら読み直します）。
- アプリには、アカウントごとに「読むだけ」にする切り替えはありません（「書き込みを許可」をオフにすると、どのアカウントも書けなくなります）。
  アカウントごとに分けたい時は、そのアカウントの claude.ai のツールの権限で決めます（足す系を「承認が必要」にするなど。§1-A の 9）。
- タイトルの「Claude に見せる」も共通です（許可の画面の見出しにも「Claude に見せるタイトル（すべての接続に共通）」と出ます）。相対比較だけに使う
  アカウントを足す時に、その許可の画面でタイトルを「見せない」にすると、推敲に使うほかのアカウントからも見えなくなります（「タイトル '…' が
  見つかりません」）。

**書き込みの順番と1日の枠（すべての接続で1つ）**

- 書き込み（推敲案・相対比較の分析・資料の記録・アイデア・ゴミ箱へ移す依頼など）は、どの接続からでも1つずつ順に行います。同じ時に頼むと、後の接続は
  前の書き込みが終わるまで待ちます（ふつうは1秒ほど。読むツールは、この書き込みの順番は待ちません）。待っている間に［連携をすべて解除］して連携し直した
  時や、その間にコネクタが接続の一覧を読み直していた時（ほかの接続の `novel_status`・1分ごとの読み直し）は、待っていた書き込みもしません（「Novel Studio
  側で連携が解除されています」）。そうでない時は、解除した接続の書き込みが遅くとも1分ほど通ることがあります（下の「できないこと・気をつけること」）。
  Firebase の答えが来ない時も、1回の要求は15秒で止めるので、待たされた接続にも1分ほどで答えが返ります。
- アプリの変更を読む（写しを新しくする）のも1つずつです。読むツールは、動いている取り込みがあれば（ほかのアカウントの書き込みが書く前に始めたものでも）
  その終わりを待ちます（アプリの1回の変更の途中までを読まないため。ふつうは1秒より短く、Firebase の答えが来ない時は15秒まで待って、前に取り込んだ内容に
  「（いまクラウドに接続できないため、前に取り込んだ内容です）」と添えて答えます）。同じ時に呼ばれた読むツール（どの接続でも）は1回の読み取りを
  分け合うので、読み取りの数は増えません。書き込みのツールは、呼ばれた後のクラウドを見るために、書く前に自分でもう1回読みます（何も変わっていなければ
  約3回）。
- 今日の読み取り・書き込みの上限、ゴミ箱へ移す1日100件、接続の要求の上限は、すべての接続で合わせて数えます（コネクタと Firebase の無料枠は1つのため）。
  `novel_status` の今日の数の行も、すべての接続を合わせた数で、接続が2つ以上の時は最後の行の前に「（読み取り・書き込みの枠と、ゴミ箱へ移す1日100件は、
  すべての接続を合わせた数です）」と出ます。上限で断る文にも「すべての接続を合わせて」と出ます（ほかのアカウントが使った分で断られた時に、
  Claude が理由を言えるように）。書き込みは、1回の呼び出しの分が残りに入らなければ何も書かずに「今日のコネクタ用の書き込み枠は、すべての接続を
  合わせて残り n 件です（この呼び出しは m 件）。…items を分けて少なくすると書けます。…」と答えます（一部だけは書きません。件数を減らして分けて
  送れば、残りの分を書けます）。新しい作品と分析1件（2件）・推敲案1件と実行の記録（2件）のように、いちばん小さく分けた呼び出しも入らない時は、
  「…分けて少なくすると書けます」の代わりに「この呼び出しは分けても入りません。」と出ます（枠が戻るまで書けません）。
- 戻る時刻はそれぞれ違います: 読み取り・書き込みの枠は日本時間16時（米国が冬時間の間は17時）、ゴミ箱へ移す1日100件は日本時間の0時、接続の要求の
  1日の上限は日本時間の午前9時。

**例1: 相対比較を2つのアカウントで同時に（それぞれのプロジェクトの PDF を分析して足す）**

- それぞれのアカウントが、自分の claude.ai のプロジェクトにある PDF を分析して足せます（同時に足しても、記録が消えたり重なったりしません）。
  ほかのアカウントのプロジェクトの PDF は、そのアカウントの Claude にしか読めません。作品の「PDF の置き場所」には、どのアカウントのプロジェクトかも
  書いておくと、後で分析し直す時に迷いません（頼む時に「PDF の置き場所は『仕事用のアカウントのプロジェクト「相対比較」』に」と言うか、アプリの
  作品の画面で書き足します）。
- 2つのアカウントで同じ本を分析する時は、片方で先に作品を足し、答えの `w:…` をもう片方のチャットに伝えて、その `w:…` で足してもらうのが確実です。
  それぞれ新しく足す時は、著者の書き方をそろえます: 作品名が同じで著者の違いが空白・「・」だけ（「村上春樹」「村上 春樹」「村上　春樹」）なら1つの
  作品に足しますが、かなと漢字の違い（「吉本ばなな」「よしもとばなな」）は別の作品になります（資料も同じ）。
- 長い分析を（1/2）（2/2）に分ける時は、1つの分析の部をすべて同じ呼び出しで送ります（別々の呼び出しで送ると、同じ日に同じ作品・観点の分析を送った
  ほかのアカウントの部と混ざって並ぶことがあります）。
- 自分の原稿の分析の回（「【原稿】原稿名（第2稿・2回目）」）は、同じ原稿の回を2つのアカウントで同時に始めないでください（どちらも一覧で同じ「次の回」の
  札を選び、1つの作品にまとまります。後の段階は観点ごとに最新の分析を読むので、2つの回が混ざります）。どうしても同時に回す時は、頼む時に回の札を
  アカウントごとに指定します（例: A に「（第2稿・2回目）」、B に「（第2稿・3回目）」）。前からある【原稿】の回に `new_work` で足した時は、答えに
  「補足: 同じ札の回がもうあったため、その回に足しました。…」と出ます（同じチャットで続けて足した時も出ますが、その時はそのままで構いません）。
- 同じ本が2つの作品になってしまった時（著者の書き方が違った・同じ札の回になった）は、作品をまとめることはできません。それぞれのアカウントで、
  残す方の `w:…` で自分の分析を足し直してもらい、もう一方の作品に足した自分の分析（`n:…`）をゴミ箱へ移してもらいます（そのチャットで足した分だけ
  移せます）。空になった作品は、アプリで削除します（Claude は作品そのものは移せません）。
- 作品批評の結果の比べた作品（`bench_works`）に、見つからない作品（ほかのアカウントがまだ足していない作品など）や、同名の作品が2つ以上ある作品名が
  あると、コネクタは結果を記録せずに断り、同名の作品の `w:…` を候補に出します（記録した後には比べた作品を足せず、送り直しても同じ内容の重複に
  なるため）。`w:…` で指して（見つからない作品は外して）送り直すと記録します。アプリの「結果を貼り付け」は、その作品を外して記録し、外したことを
  確かめの画面に出します（貼り付けた答えをそのまま記録できるように）。

**例2: 推敲と相対比較を別のアカウントで同時に（A で相対比較、B で原稿の推敲）**

- B で推敲（`novel_read_text` で読み、`novel_add_proofreading` で足す）をしている間に、A で相対比較を足しても、どちらもそのまま使えます。B の
  推敲案の追加は、A の書き込みの途中ならその終わりを待ちます（上の「書き込みの順番」）。B が読むのは、A の書き込みの順番は待ちませんが、A の書き込みが
  書く前に始めたアプリの変更の取り込みが動いていれば、その終わりを待ちます（ふつうは1秒より短く、Firebase の答えが来ない時は15秒まで）。
- 1日の書き込みの枠（5,000 回）は A と B で合わせて数えます: `novel_add_proofreading` は1回で items の数＋1回（実行の記録）、相対比較は新しい作品と
  分析 N 件で 1＋N 回（作品が前からあれば N 回）。100話を1話100件ずつ推敲すると 10,100 回で1日に入らないので、何日かに分けるか、1話の件数を
  減らします（相対比較で作品20・分析各14件（300 回）と同じ日なら、推敲に使えるのは約 4,700 回 = 100件の呼び出しで約 46 回）。読み取りの数は §6。
- 枠が足りない時の答え「今日のコネクタ用の書き込み枠は、すべての接続を合わせて残り n 件です（この呼び出しは m 件）」には残りが出るので、Claude は
  items を減らして残りの分を書けます。使った数は、どちらのアカウントの `novel_status` でも「今日（太平洋時間 …）の読み取り n / 15,000・
  書き込み n / 5,000」に出ます。
- 長い答えを続き（`cursor`）で読んでいる間に、ほかのアカウントやアプリが中身を変えても（話を並べ替えた・特殊ブロックを足した、推敲案を足した・
  チェックした、分析・記録を足した・ゴミ箱へ移した・書き換えた）、続きは読んでいた話・分析・記録を id で探し直し、推敲案の一覧は前の答えの最後の案の
  次から続けるので、範囲の中で黙って同じ所をもう一度出したり、読んでいない所を飛ばしたりしません（範囲を番号で指した時の例外は次の項目）。前の方に入った・
  動いた所がある時は、答えの先頭（続きの見出しより前）に「（話の並びが変わりました。…）」「（分析が増えました。前回の続きより前に n:…「01 構成」が入りました（まだ読んでいません。
  analysis_id で読めます）。…）」「（前の答えの後に推敲案が n件増えました。…）」のように出ます。そのまま続けてよく、知らせに出た読んでいない話・分析は
  `pieces`・`analysis_id`・`note_id` で読むか、cursor なしで読み直します。2.9 にする前の cursor も、そのまま続きを読めます。
- 範囲を番号（`from`・`to` の `#3`・「第3話」、`pieces` の番号）で指して続き（cursor）で読んでいる間に、続きより後ろへ話・特殊ブロックが入ると、範囲は
  呼ぶたびに番号で決め直すので、範囲の最後の話が外れて、知らせなしに読まれないことがあります（推敲案の一覧の確認の範囲の「未確認」で分かります）。
  短い id（`p:…`）で指せば外れません。
- 推敲案の確認の範囲は、推敲案を足した接続（アカウント）の Claude が `novel_read_text` で読んだ時の本文で残します。読んだ後に作者がアプリで直した話は
  「本文が変わった話」になり、答えの補足にも出ます。ほかのアカウントが読んだことは数えません（読んでいない話を `covered` に入れた時は、今までどおり
  足した時の本文で確認済みになります）。検索（`novel_search_text`）は読んだことにしません。24時間より前に読んだ話も、今までどおりです。

**できないこと・気をつけること**

- どのアカウント（接続）が足したかは、記録に残らず、アプリにも Claude の答えにも出ません（「Claude が作成」の印と「（2026-10-29・Claude）」だけ）。
  分けたい時は、アカウントごとに別の作品・別の話を頼みます。
- どの接続の Claude も、ほかのチャット・ほかのアカウントが足したカード（`n:`・`k:`・`i:`）をゴミ箱へ移す依頼・アイデアへの追記ができます（コネクタは
  見分けません。ツールの説明で「そのチャットで自分が登録した id だけ」を指すよう Claude に伝えてあります）。どのアカウントでも「カードをゴミ箱へ移す」は
  「承認が必要」にしておき、移すカードを確かめてください。足したチャットがもう無いカードは、アプリで削除します。
- 1つの作品の観点を2つのアカウントで分けて分析すると、観点のまとまりは届いた順に並びます（B の 08〜14 が先に届くと、08〜14 の後に 01〜07）。
  順に並べたい時は、1つの作品は1つのアカウントで分析します。
- 2つのアカウントがそれぞれ同じ作品に「14 検索用タグ」を足すと、自動で付くジャンルは、アプリがいっしょに受け取ったか（新しい方だけ）、別々に
  受け取ったか（両方）で変わることがあります。
- 同じ話を2つのアカウントで推敲すると、同じ案は1つだけ残り、後の実行は「0件」と出ます（重複）。直し方の違う案は、同じ所に2つ残ります。
- アプリで作品を削除するのと同じ時に、ほかのアカウントがその作品に分析を足すと、答えは「追加」でもアプリには出ません（作品をゴミ箱から戻すと出ます）。
- 解除した接続は、遅くとも1分ほどで止まります（その間の書き込みは通ることがあります）。

## 3. 更新する時

```
git pull
npm ci
npm --prefix connector ci
npm run deploy
```

`npm run deploy` は、アプリ・アクセスルール・コネクタをまとめて公開します（`connector.local.json` がある時だけコネクタも）。

2.6 から 2.7 に上げた時は、claude.ai の「カスタマイズ → コネクタ → Novel Studio」のツールの権限に「カードをゴミ箱へ移す」が増えます。
このツールだけは「承認が必要」にしてください（ほかのツールは今のままで構いません。§1-A の 9）。2.7 はデータの形の版を上げるので、
公開の前に開いているアプリをすべて読み込み直します（[DEPLOY.md](DEPLOY.md) の 4「2.6 から 2.7 に上げる時」）。
コネクタは、どれかの端末で 2.7 のアプリが同期するまで書き込みを止めます（「アプリの版が古いままです」。読むのは続けられます）。

2.7 から 2.8 に上げた時は、ツールの権限に「アイデアを足す」「アイデアに追記」が増えます（ツールは 24。ツールの一覧を読み直してください）。
この2つは何も消さないので「常に許可」で構いません。「カードをゴミ箱へ移す」は今までどおり「承認が必要」のままにします（§1-A の 9）。
2.8 もデータの形の版を上げるので、公開の前に開いているアプリをすべて読み込み直し、**公開したらすぐに 2.8 のアプリを一度開いて同期してください**
（[DEPLOY.md](DEPLOY.md) の 4「2.7 から 2.8 に上げる時」）。どれかの端末で 2.8 のアプリが同期するまで、コネクタの書き込み（名作分析の
`novel_add_bench_analysis` も）はすべて止まります（`novel_status` に「アプリのデータの形: 6（コネクタは 7。書き込みは止まります）」。読むのは続けられます）。

2.8 から 2.9 に上げた時は、ツールの数と権限は変わりません（「アイデアを足す」に入力 `folder`・`subfolder`・`theme`・`placement` が増えます）。
2.9 もデータの形の版を上げるので、2.8 と同じく公開の前に開いているアプリをすべて読み込み直し、**公開したらすぐに 2.9 のアプリを一度開いて同期して
ください**（[DEPLOY.md](DEPLOY.md) の 4「2.8 から 2.9 に上げる時」。それまでコネクタの書き込みは止まります）。
- アクセスルールとコネクタを必ず一緒に更新します（`npm --prefix connector ci` をしてから、`npm run deploy` を `connector.local.json` のあるパソコンで）。
  `npm run deploy` は Web 版とアクセスルールを公開してからコネクタを公開するので、コネクタの所だけ失敗した時（「コネクタの部品が入っていません」・
  Cloudflare へのログインが切れている・wrangler のエラー）は、2.9 のアプリが、まだ 2.8 のコネクタ（データの形 7）には「コネクタがまだこのアプリの版に
  なっていません」と出して許可しません（2.8 のコネクタは、許可するたびにほかの接続を切るため）。`connector.local.json` が無いまま続けた時は、アプリが
  「コネクタ未設定」になります（この節の終わり）。どちらの時も、いまの接続で読むことはできますが、2.9 のアプリが同期した後は、書き込み（名作分析の
  `novel_add_bench_analysis` も）がすべて「アプリが新しい版のデータを書いています（データの形 8、コネクタは 7）。npm run deploy でコネクタを更新して
  ください…」と止まります。直してから、もう一度 `npm run deploy` を実行してください。
- 公開している間は、新しく接続しないでください。2.8 のままのタブでは許可できず（新しいアクセスルールが 2.8 の形の記録を断ります）、その
  ［連携を解除］はすべての接続を外します。
- いまの接続はそのまま使え、`novel_status` の最後に「この接続: 接続1（接続 1 / 10。…）」が出ます。2.8 で別のアカウントを接続した時に切れた
  アカウントは、claude.ai でもう一度「接続」を押してください（§2-E）。
- claude.ai では新しいチャットを始めます（§2-D の 7）。

`connector/wrangler.jsonc` を書き換えた時（§5 の `WORK_BUDGET_CHARS`・`limits`、§6 の `DAILY_READ_BUDGET`・`DAILY_WRITE_BUDGET`、Claude Code 用の `ALLOW_CLAUDE_CODE`）は、`git pull` が
「Your local changes … would be overwritten」で止まることがあります。その時は `git stash` → `git pull` → `git stash pop` の順に実行してから続けてください。

`connector.local.json` は、`npm run connector:setup` を実行したパソコンにだけあります（Git には入りません）。別のパソコン
（Windows と Mac など）から更新する時は、そのパソコンでも先に一度 `npm run connector:setup` を実行するか（同じコネクタ・KV・鍵・連携を
そのまま使います）、`connector.local.json` をそのパソコンのリポジトリの直下にコピーしてください。無いまま `npm run deploy` をすると、
公開したアプリは「コネクタ未設定」になり（claude.ai から接続し直せなくなります）、コネクタも更新されません（`npm run deploy` が注意を出して聞きます）。

## 4. やめる時・止める時

| したいこと | 方法 |
| --- | --- |
| すぐに止める | アプリの 設定 → Claude 連携 →［連携をすべて解除］（その場でコネクタは何も読めなくなる。もう一度使う時は claude.ai で接続し直す）。Firebase に繋がらない間や無料枠を使い切った間は、それでも前に取り込んだ内容を読めることがある（書き込みはできない）。すぐに切るには claude.ai の「カスタマイズ → コネクタ → Novel Studio」でもコネクタを削除する |
| 1つのアカウントの接続だけ止める（2.9） | 同じ画面の接続の一覧で、その接続の［この接続を解除］（次に使った時から。遅くとも1分ほどで読めなくなる。ほかの接続はそのまま。どの名前がどのアカウントかは、そのアカウントの Claude の `novel_status` の最後の行「この接続: …」で分かる）。Firebase に繋がらない間や無料枠を使い切った間は、解除した接続でも前に取り込んだ内容を読めることがある（書き込みはできない）。すぐに切るには claude.ai 側でもその接続を外す |
| 書き込みだけ止める | 同じ画面の「書き込みを許可」をオフ（読むのは続く。アイデアを足す・追記・ゴミ箱へ移す依頼も止まる。アクセスルールで止まる。もうクラウドにある依頼は、アプリが同期した時に当てる） |
| あるタイトルだけ見せない | タイトル画面の「Claude に見せる」のチップで「見せない」を選ぶ |
| claude.ai から外す | 「カスタマイズ → コネクタ → Novel Studio」でコネクタを削除 |
| コネクタそのものを消す | リポジトリの直下で、次の3つ: ① `npx --prefix connector wrangler delete --name novel-studio-connector`（Cloudflare から Worker が消える）② OAuth 用の KV `novel-studio-connector-oauth-kv` を消す（Cloudflare のダッシュボードの「ストレージとデータベース → KV」で削除。または `npx --prefix connector wrangler kv namespace list` で id を調べて `npx --prefix connector wrangler kv namespace delete --namespace-id <id>`）③ `connector.local.json` を消す（PowerShell は `Remove-Item connector.local.json`、Mac は `rm connector.local.json`）。その後で一度 `npm run deploy`（アプリからコネクタの URL を外す）。鍵を消すだけなら `npx --prefix connector wrangler secret delete TOKEN_ENC_KEY --name novel-studio-connector` |

完全にやめる時は、アプリで［連携をすべて解除］してから claude.ai でコネクタを削除し、Cloudflare からも消すなら上の「コネクタそのものを消す」の3つをすべて
行ってから `npm run deploy` を実行してください（KV か `connector.local.json` が残っていると、後の `npm run deploy` がコネクタを作り直そうとして失敗するか、
消したコネクタが戻ってきます）。

| 「今日のコネクタ用の読み取り枠を使い切りました」 | アプリの同期の分を残すための上限（1日 15,000 回。すべての接続を合わせて）。日本時間16時（米国が冬時間の間＝11月上旬〜3月中旬は17時）に戻る。読むツールは前に取り込んだ内容で答え、書き込みは止まる |

| 「今日のコネクタ用の書き込み枠を使い切りました」 | 1日 5,000 回の書き込みの上限（すべての接続を合わせて。ほかのアカウントが使った分も入る）。同じ時刻に戻る。使った数は `novel_status` の「今日（…）の読み取り n / 15,000・書き込み n / 5,000」。推敲を何十話も続ける日は、何日かに分ける（§2-E の例2・§6） |
| 「今日のコネクタ用の書き込み枠は、すべての接続を合わせて残り n 件です（この呼び出しは m 件）」（2.9） | 残りはあるが、この呼び出しの分が入らない（何も書いていない。一部だけは書かない）。`items`（ゴミ箱へ移す時は `cards`）を n 件より少なく減らして送れば、残りの分を書ける（推敲案は items の数＋1回、相対比較の新しい作品は分析の数＋1回）。「この呼び出しは分けても入りません」と続く時は、いちばん小さく分けても入らない（新しい作品と分析1件、推敲案1件と実行の記録など）。枠が戻る時刻まで待つ |
| 作品批評の結果で「- 比べた作品が決まらない 作品批評の結果: bench_works の '…' は、相対比較に同名の作品が2件あるため、どれか決まりません」「- 見つからない …: …は相対比較に見つかりません」（2.9） | 結果はまだ記録していない。候補の `w:…` で指すか、見つからない作品を外して送り直す |
| 続きの答えの先頭（「=== …の続き」の行より前）に「（話の並びが変わりました。…）」「（分析が増えました。…）」「（前の答えの後に推敲案が n件増えました。…）」（2.9） | 前の答えの後に、アプリかほかのアカウントが話の並び・推敲案・分析・記録を変えた。続きは重ねず抜かずに読めているので、そのまま続けてよい。「まだ読んでいません」と出た話・分析・記録は `pieces`・`analysis_id`・`note_id` で読むか、cursor なしで読み直す（§2-E。範囲を番号で指した時の例外も §2-E） |
| Claude が「1回の呼び出しが大きすぎます（送る内容は合わせて 1,000,000 バイトまで…）」と言う（2.9 より前は英語の「Payload Too Large」） | 1回のツールの呼び出しで送れるのは、合わせて 1,000,000 バイト（日本語でおよそ 33万字）まで。超えた呼び出しは何も受け取らず、何も書いていない（claude.ai には HTTP 413 と、この文の JSON-RPC のエラーが返る）。`items` を減らして、いくつかの呼び出しに分けて送ってもらう（1件の記録の上限 JSON で 200,000 字とは別で、長い items が多い時に出る。1回の答えで書く量としては、実際にはまず届かない） |
| 「Firebase の今日の無料枠を使い切りました」 | アプリの同期も止まっている。同じ時刻に戻る |
| Cloudflare の Workers Logs に「Exceeded CPU」が続く | 無料プランの CPU の上限（10ms）を超えている（大きなタイトルを2つのアカウントで同時に使うと、片方が書いた後のもう片方の最初の読み取りで、見せ方を作り直す分だけ届きやすい）。Workers Paid（月 5 USD）に切り替える（コードの変更は要らない）。切り替えたら `connector/wrangler.jsonc` の `limits` と `WORK_BUDGET_CHARS` を上げてもよい |

ログ（Cloudflare の「Workers & Pages → novel-studio-connector → Logs」）には、原稿・トークン・URL の問い合わせ部分は出しません。

## 6. 無料枠の目安

| 項目 | 無料枠 | コネクタの使い方 |
| --- | --- | --- |
| Cloudflare Workers のリクエスト | 1日 10万回 | 1回のツールの呼び出しで数回 |
| Cloudflare KV の書き込み | 1日 1,000回 | トークンの更新（1時間ごと）1回で2回、接続の要求（claude.ai の「接続」から同意の画面の［Novel Studio で確認する］まで）1回で2回、連携を終えるまで1回で約5回。2.9 の複数の接続を10使い続けると、更新だけで1日に約 480 回。接続の要求はコネクタ全体で1日 150 回まで（ほかの人に上限まで送られても 300 回）なので、合わせても 1,000 回に届かない |
| Firestore の読み取り（アプリと共通） | 1日 5万回 | 連携した直後に全件を1回（記録の数だけ）。その後はツールの呼び出しごとに、前の取り込みを最後まで読んでから15秒以内なら0回、それ以外は変わった記録の数と50件ごとに2回（何も変わっていなければ3回。同じ時の読むツールの呼び出しは、どの接続からでも1回の読み取りを分け合う。書き込みのツールは同じ時でもそれぞれ読む）。コネクタが書いた記録も、次の呼び出しで1回ずつ読み直す（推敲案 100件の後は約 107 回、相対比較の新しい作品と分析14件の後は約 17 回）。連携の記録（`config/connector`）は1分ごとに読み直し（トークンの更新の時も。書き込みの停止中に書こうとした時は、断る前に5秒ごと）、書き込みのツールはデータの形の版（`meta/app`）も1分ごとに読む（どちらも1回3回）。書き込みのツールの呼び出しは、書く前の確かめで1回 3〜9 回。休まずに呼び続けても1時間に約 900 回まで（5秒ごとでも。30秒ごとなら約 540 回。時間で決まり、アカウントの数ではほとんど増えない。2つのアカウントがいつも同じ時に呼ぶと、連携の記録の読み直しの分だけ増えて約 1,080 回）。コネクタは1日 15,000 回までで止まる（すべての接続を合わせて。書き込みは、残りが端末の変更を読む1回分（50 件ほど）より少なくなると止まる） |
| Firestore の書き込み（アプリと共通） | 1日 2万回 | 足した記録の数だけ（推敲案は items の数＋1回で、100件なら 101 回。相対比較の新しい作品と分析14件で 15 回。断られて書けなかった分は数えない。答えが届かない・Google 側の一時的な失敗が続いたなどで書けたか分からない分は数えたまま（書けていなかった時は、その分多めに数える）、答えが届かずに試し直して「もうある」になった分は書けた分として数える）。コネクタは1日 5,000 回までで止まる（すべての接続を合わせて。1回の呼び出しの分が残りに入らなければ、その呼び出しは何も書かずに残りの数を答える）。5,000 回は Firebase の2万回の4分の1で、残りをアプリの同期（保存・端末の間の受け渡し）に取っておくため。100話を1話100件ずつ推敲する（10,100 回）と1日に入らない（§2-E の例2） |

コネクタが書いた記録は、オンラインの各端末が1回ずつ読みます（推敲案を1日 4,000 件足すと、端末3台で約 12,000 回。コネクタの読み取りと合わせても
5万回の半分ほど）。

コネクタの1日の枠は `connector/wrangler.jsonc` の `DAILY_READ_BUDGET`（15,000）と `DAILY_WRITE_BUDGET`（5,000）です。変える時はこの値を書き換えて
`npm run deploy` を実行します（書き換えると `git pull` が止まることがあります。§3）。書き込みを1回増やすと、コネクタと各端末の読み取りも1回ずつ
増えるので、Firebase の無料枠（書き込み 2万回・読み取り 5万回。アプリの同期と共通）に収まる値にしてください。コネクタの Durable Object（Vault）も、
記録を1件書くと写しに数行（測ると約6行）を書きます。書き込みの枠を上げた時は、Cloudflare のダッシュボードで Durable Objects の使用量も確かめてください。

## 7. 安全のための決まり（要点）

- 受け付けるのは claude.ai の公開の識別子（`https://claude.ai/oauth/mcp-oauth-client-metadata`）と、claude.ai / claude.com の決まった戻り先だけ。
  接続の要求は、1つのネットワーク（IPv4 のアドレス・IPv6 の /48）から1時間10回・1日20回まで、コネクタ全体で1日150回まで
  （いたずらで OAuth の KV の書き込み枠を使い切られないように。IP はそのまま残さず、ログにも書かない）。同意の画面の［Novel Studio で確認する］は、
  同じ同意では1回だけ通す（送り直すと「この接続の要求はもう使われています」）。
  claude.ai で「接続」を押して「接続の要求が多すぎます」と出た時は、ほかの人がいたずらで送っているのかもしれません。
  「このネットワークから」なら1時間ほど待つか、Wi-Fi とモバイル通信を切り替えて接続し直す。「今日は多すぎます（全体で…）」なら
  日本時間の午前9時を過ぎてから。どちらも、いま使えている接続（トークンの更新）には関わりません
- 同意は覚えない（接続のたびに確かめる）。トークンは1時間、更新用トークンは180日使わなければ切れる
- 連携の許可: アプリが `config/connector` に `pairing = sha256(s + "." + k)`（`s` は claude.ai から始めた接続の印、`k` はアプリの中で作った乱数）を書き、
  コネクタは「claude.ai から始めたブラウザの cookie」と「アプリが渡した k」の両方がそろい、15分以内で、まだ使っていない時だけ完成させる
- OAuth の許可は、その時の連携（持ち主と、`config/connector` を作った時刻 = 連携の代）と、接続（2.9。claude.ai で接続するごとの id。アプリが
  乱数で作り、使い回さない）に結び付ける。［連携をすべて解除］すると、その後に連携し直しても（別の Claude のアカウント・別の戻り先からでも）前の
  許可は使えない（ツールは 401、トークンの更新は断られる）。接続を足す（2.9 からは前の接続を取り消さない）・名前を変える・「書き込みを許可」を
  切り替えるだけなら、前の許可も使える。接続の一覧から外した接続（［この接続を解除］・入れ替え）の許可は、次に使った時にその許可だけ取り消す。
  連携の記録はどのツールの前にも・トークンの更新の前にも1分ごとに読み直し、一覧に無い接続は5秒以内に読み直してから断る（古い写しで正しい許可を
  取り消さない）。ほかの接続の書き込みの後ろで待った書き込みは、書く前にもう一度、最後に読んだ一覧と連携の代で確かめる（待つ間に［連携をすべて
  解除］して連携し直された接続、待つ間に読み直した一覧から外れていた接続は書かない。読み直していなければ、外した接続は最大1分書ける）。2.8 までの
  許可は接続「接続1」として扱う
- 接続は10まで（アプリとアクセスルールの両方で）。`config/connector` を書けるのは持ち主だけ（コネクタの匿名のアカウントは書けない）。新しい許可は、
  その接続の指紋と時刻（サーバー時刻）がそろう時だけ。指紋は接続ごとに持つので、15分の間に2つ許可しても両方確かめられる
- 受け付けない `client_id`（公開の識別子の URL）は、取りに行く前に断る（`/authorize`・`/oauth/token`）。トークンの要求の `client_assertion`
  （鍵で署名したクライアント認証。claude.ai は使わない）も、取りに行く前・KV に書く前に断る
- コネクタの URL はアプリに組み込む（`connector.local.json` からビルドの時に）。リンクの中の URL やコネクタの身元は信用しない
- コネクタの書き込みは「無い時だけ作る」（内容から作った id）。同じ結果を2回送っても1つ、アプリで削除した推敲案は「以前に削除」で戻ってこない
  （ゴミ箱から消えて30日たった後は、削除の印をもとに判断する）
- ゴミ箱へ移す依頼（2.7）は、アプリが確かめてから移す。移せるのは Claude がコネクタで作り、作者が直していない相対比較の分析・資料の記録だけで（2.8 からは Claude のアイデアも。次の項）、
  1日100件まで、必ずゴミ箱へ（30日は戻せる）。依頼の id は表とカードから作り、ゴミ箱の件の id は依頼から決める（2台の端末が同じ依頼を処理しても1件）
- Claude のアイデア（2.8）は、アクセスルールで id を `cy-…`（追記の依頼は `cu-…`）に決め、作るだけ。アプリは source と id の形の両方で
  「Claude が作ったアイデア」と見分け、追記もゴミ箱へ移すのもそれだけに当てる（作者のアイデアには追記しない・移さない）。追記は1回20,000字・
  1枚100,000字まで、前の中身を消さない。「作者が直した」は本文の指紋で決める（済み・並べ替え・仕切りの移動・Claude の追記は数えない）。
  ルールはアイデアのタイトルを見られないので、「読む＋書き込む」のタイトルかはコネクタが確かめ、追記とゴミ箱へ移す依頼はアプリがもう一度確かめる
- Claude のアイデアのフォルダ（2.9）は、アクセスルールで id を `cf-…` に決め、作るだけ（JSON は 2,000 字まで）。作者のフォルダの名前の変更・移動・
  削除、カードの移動はできない。カードと一緒にだけ作ること・書けるタイトル／ホームにだけ作ることはコネクタが守り、ルールが読めないつながりの
  食い違い（3段目・別の仕切りの親やフォルダ）は、アプリとコネクタが見せ方で外す（2段までに見せ、ほかの仕切りのフォルダにはつながない）
- Cloudflare のアカウントを乗っ取られると、原稿を読まれる・不要な記録やアイデア・追記を足される・Claude が作ったカードをゴミ箱へ移される（戻せます）恐れがあります
  （書き換え・それ以外の削除・アカウントの乗っ取りはできません）。
  Cloudflare のログインは必ず2段階認証で守ってください（Google で登録した場合は Google アカウントの2段階認証）。止める時はアプリの［連携をすべて解除］がいちばん早い

## 9. 開発者向け

```
npm run test:connector        # 単体テスト・Workers の実行環境（workerd）のテスト・公開する形の確かめ
npm run test:connector:emu    # Firebase エミュレーターでの結合テスト（本番のアクセスルール・アプリの端末と一緒に。Java が必要）
npm run test:e2e:sync         # ブラウザでの同期の E2E。e2e/pairing.sync.spec.ts は本物のコネクタ・アプリの画面・エミュレーターで連携を通しで確かめる
npm --prefix connector run typecheck
npm --prefix connector run gen-schemas    # ツールの入力の形（src/mcp/schemas.ts）を変えた時
npm --prefix connector run bundle-check   # dexie・firebase・react・zustand が入っていないか
```

- `connector/src/index.ts`: OAuth の設定（`@cloudflare/workers-oauth-provider`）・毎日の片付け
- `connector/src/auth/`: 受け付けるクライアント・同意の画面・連携の確かめ（`/authorize`・`/pair/callback`・`/connect/identity`）
- `connector/src/mcp/`: MCP のサーバー（`@modelcontextprotocol/server`。状態を持たない）・ツールの一覧・入力の形・サーバーの説明
- `connector/src/vault/`: Vault（Durable Object）の中身（身元・写し・書き込み・数の上限・ツールの結果の文字の形）
- 入力の上限（短い項目と件数だけ）は `src/claude/records.ts` の `RECORD_LIMITS`（ツールの JSON Schema の `maxLength` と同じ値。
  長い文章には `maxLength` を付けない）。コネクタが書く1件の記録の大きさ（JSON にして 200,000 字）は同じファイルの作り方と
  `connector/src/vault/writer.ts` で確かめ、超える時は分け方を書いたエラーを返す
- アプリの純粋な部品（`src/domain`・`src/claude`・`src/sync/codec.ts`・`merge.ts`）をそのまままとめて使う（文字数・話数・id・推敲案の場所がアプリと同じ）
- アプリとの連携の決まり（連携の画面の URL・`/connect/identity` の答え・k・指紋 `sha256hex(s + '.' + k)`・`/pair/callback` の引数・15分）は
  `src/claude/pairing.ts` にあり、アプリの連携の画面（`src/features/claude/connectLogic.ts`）とコネクタ（`connector/src/auth/routes.ts`・
  `connector/src/vault/core.ts`）が同じものを使う。決まりの値は `src/test/pairingFixture.ts`（両方のテストで使う）
- `e2e/pairing.sync.spec.ts`: wrangler の `createTestHarness` でこの Worker をテストの中に立ち上げ（workerd。Durable Object・KV も本物）、
  ブラウザのアプリ（開発サーバー）からコネクタへの通信をそこへ渡して、接続 → 同意 → アプリで許可 → トークン → ツール → 書き込みの停止 →
  2つ目の接続（2.9。両方のトークンが使える）・名前を変える・1つ解除（その接続だけ 401）→ 連携をすべて解除 を確かめる。claude.ai の代わりはテストが務める（クライアントは DCR で登録。CIMD は workerd のテストで確かめる）。
  コネクタの部品が無ければ飛ばす
- 手元で動かす: `npx firebase emulators:start --config firebase.emu.json --only auth,firestore --project demo-novel-studio` を動かしたまま、
  `connector/.dev.vars` に `FIREBASE_EMULATOR_HOST=127.0.0.1`・`FIREBASE_PROJECT_ID=demo-novel-studio`・`FIREBASE_API_KEY=fake-api-key`・
  `TOKEN_ENC_KEY=（16字以上の適当な文字）`・`APP_ORIGIN=http://localhost:5173`・`ALLOW_LOCALHOST_APP=true` を書いて `npm --prefix connector run dev`
  （`.dev.vars` は Git に入りません。手元の Vault・KV の中身は `connector/.wrangler/` に残り、消すと最初からになります）
  動いていれば `http://localhost:8787/` に「未連携」と出て、`/connect/identity` がエミュレーターの匿名の身元を返します
- アプリもこの手元のコネクタにつなぐ時は、もう1つの画面で開発サーバーを動かします（`connector.local.json` があれば、そちらが優先されます）
  - Mac（ターミナル）: `VITE_FIREBASE_EMULATOR=127.0.0.1 VITE_CONNECTOR_ORIGIN=http://localhost:8787 npm run dev`
  - Windows（PowerShell）: `$env:VITE_FIREBASE_EMULATOR="127.0.0.1"; $env:VITE_CONNECTOR_ORIGIN="http://localhost:8787"; npm run dev`
    （`$env:` は PowerShell の画面を閉じるまで残ります。開発サーバー用の画面で動かし、終わったら閉じてください。同じ画面で公開する時は先に
    `Remove-Item Env:VITE_FIREBASE_EMULATOR, Env:VITE_CONNECTOR_ORIGIN -ErrorAction SilentlyContinue`。`npm run deploy` はこれらを公開するアプリに入れません）
  - 設定 → Claude 連携 に `http://localhost:8787/mcp` が出ます。連携の画面（`#/claude/connect`）は claude.ai の接続から開かれるので、
    手で通して試すより `e2e/pairing.sync.spec.ts` を動かす方が確実です
