# Novel Studio 仕様書

小説執筆アプリ。PWA（React + TypeScript + Vite）として作り、デスクトップ・iOS・Android のブラウザ／ホーム画面アプリで動く。データは端末内の IndexedDB に保存する（サーバーなし）。

## 1. 要件（原文の要約）

1. **アイデアリスト**: タイトルごとにあらかじめ仕切られている。タイトルを増やすほど仕切りが増える。どのタイトルにも属さないスペースもある。
2. **タイトルごとの管理**: 以下はすべてタイトルの配下に属する。
3. **設定項目**: キャラクター・世界観など。項目そのものを後から任意に追加できる。
4. **章管理のオン/オフ**（大長編向け）: 章をフォルダにして、その中に話を入れ、話順に任意にソートできる。
5. **話数単位の原稿管理**（コピー機能あり）: 推敲のため1話に複数バージョンを持てる。採用するバージョンをアクティブにするボタンがある。アクティブにした採用原稿だけが上位の層（章・タイトル）に反映される。原稿の管理単位は必ず「第n話」。第n話の下に話の題を任意に付けられる。階層は タイトル → 章（大長編の場合）→ 第n話。
6. **戦略**: 執筆中・完了後に、どのコンテストにどの順番で応募するか、結果はどうだったか、それを踏まえた改稿方針、コンテストの概要を踏まえた再応募方針など、商業的なアプローチを戦略的に管理する。
7. **見え方**:
   - 起動するとアイデア領域とタイトル群が表示される。
   - タイトルに入ると、設定項目・章（有効時）・アクティブな話が話数順に表示される。
   - **（肝）** アクティブ化されている話を開くと原稿が表示され、その右側（デスクトップ）／下側（iOS/Android）に推敲バージョンの一覧が表示される。任意のバージョンを選ぶと、現在の採用原稿と選んだバージョンを同じウインドウ内で並べて比較できる。左右・上下の比率はスライドで変更できる。
8. **追加の種類**: タイトルから追加するときは必ず「メモ」「話数追加」「特殊追加」から選ぶ。
   - **メモ**: タイトル付きの付箋。タイトル内で表示優先度が最も低く、常に一番下に配置。
   - **話数追加**: 強制的にその時点の最新話が作られる（作成直後なら第1話、次は第2話…）。**第n話の表記は変更できない**。ソートはでき、ソート後は並び順どおりに話数が書き換わる。**途中の話数は削除できない**（例: 第1〜4話で第2・3話を消して空洞化はできない。第4話を第2話にソートして詰めてから旧2・3話を削除する）。話数順を変えずに、その話のすべての原稿を非アクティブにすることはできる。その場合、通し読みでは該当話に「採用原稿がありません。」と表示される。
   - **特殊追加**: 話数に属さないブロック（プロローグ・エピローグ等）。話数が固まった後からでも差し込める。第n話の部分を任意に編集できる。

## 2. 設計上の決定

- **話数は保存しない**。`Title.structure`（タイトル直下の並び）と `Chapter.pieceIds`（章内の並び）から常に導出する（`src/domain/structure.ts`）。これで「表記変更不可」「ソートで話数が書き換わる」を構造的に保証する。
- 話（`Piece`）は `kind: 'episode' | 'special'`。special は話数を消費せず、`label` を自由に編集できる。2.2 から幕（`'act'`。幕に分けた話の中だけにあり、本編の並びには載らない）も加わった（[SPEC-2.md](SPEC-2.md) の 6.）。
- **削除ルール**: episode は採番スコープ内の最後の話だけ削除可能（`canDeletePiece`）。special はいつでも削除可能。
- **話数の振り方**（章が有効なときのみ選べる）: `continuous`（通し番号・既定）／`perChapter`（章ごとに第1話から）。章が無効なときは常に通し番号。
- **話数追加の位置**: 通し番号では必ず全体の最新話になる位置（最新話の直後）。章を指定した場合も、最新話より前の章には追加できない（`episodeTargets` が候補を返す）。章ごとモードでは指定章の最新話になる。話や章より後ろにあるタイトル直下の特殊ブロック（エピローグ・あとがき等）より前に入る。新しい章も同じ位置に入る。
- **章の有効化**: 初回は「第1章」を作り既存の話をすべて入れる（話数は変わらない）。無効化しても章構成は保持し、平坦に表示する。再度有効にすると元の章構成で表示される。
- **章の削除** = 章の解除。中の話は章があった位置に章の外として並ぶ（話は消さない）。
- **並べ替え**: 1つ上/下（`movePieceStep`）と、位置を選んで移動（`movePiece` + `insertOptions`）。章が有効なとき、章の先頭から上へ動かすと章の外へ出て、章の外から章の方向へ動かすとその章の端に入る。章が無効な間に隠れた章の境目をまたいで1つ動かした時は、各章の話数を保ったまま読む順だけ入れ替える（↑→↓で元に戻り、章をオンに戻しても構成が崩れない）。
- **推敲バージョン**: 作成時に「第1稿」が作られ採用中になる。複製すると `第n稿（第m稿を複製）`、新しい稿を足すと `第n稿`。採用は1つだけ、または採用なし。
  - **n の決め方**: その話（幕）に今ある稿（採用・不採用を問わない）のいちばん大きい番号＋1。番号のある稿が無ければ1。ゴミ箱の稿・完全に削除した稿は数えず、間の欠けた番号は埋めない（第1稿だけなら次は第2稿、第1・3・5・6稿なら次は第7稿）。幕の操作で作る稿（「第n稿（分割）」「第n稿（つないだ稿）」「第n稿（幕をつないだ稿）」。[SPEC-2.md](SPEC-2.md) の 6.）も同じ（`src/domain/versionNumber.ts`）。
  - **番号は稿の名前から読む**（保存しない）: 名前の先頭（前の空白は除く）の「第n稿」の n。半角・全角の数字と漢数字（「第三稿」「第二十一稿」「第一〇稿」）を読み、後ろの「（第2稿を複製）」「（分割）」「（競合: iPhoneでの編集）」「（復元）」などは読み飛ばす。稿の名前を書き換えれば書き換えた番号で数え（「第10稿」にすれば次は第11稿）、「改稿版」のように「第n稿」で始まらない名前にした稿は番号なしとして数えない。
  - **ゴミ箱から戻す時**: 戻す先の話・幕に同じ名前の稿が今あれば、戻す稿を「第3稿（復元）」（それもあれば「（復元2）」「（復元3）」…）にして戻す（削除した後に同じ番号の稿を作っていることがあるため。先頭の「第3稿」は残る）。重ならなければ名前は変えない。同期の競合で残す稿の名前（「（競合: …）」）は今までどおり。
  - **2台の端末で同時に稿を作った時**は、同じ番号の稿が2つできることがある（どちらも第4稿など）。まれで、本文はどちらも残り、名前は書き換えられるので、そのままにする。
  - `Piece.versionSeq`（以前の連番）は、古い版のアプリ・同期のために残すが名前には使わない。稿を作る時に、作った番号と稿の数まで進める（小さくはしない。同期で揃える決まりも今までどおり）。
- **メモ**: 本編とは別リストで、タイトル画面の一番下に表示。
- **アイデア**: `titleId = null` が「どのタイトルにも属さない」。タイトルを削除すると、そのアイデアは「どのタイトルにも属さない」へ移る。
  - **内容だけ**（見出しはない）: 追加・編集ダイアログとすばやく追加は内容の入力欄1つだけ。カードは内容を出し、2行以上あれば1行目を少し太くする。古い版で付けた見出し（`Idea.heading`。型と古いデータのために残す）は、空でなければ編集して保存するまでは見出しとして表示する。編集ダイアログでは見出し＋改行＋内容を1つの入力欄に入れて開き（「見出しは内容の1行目に入れました」と添える）、保存すると内容がその文章に、見出しが空になる。開いて閉じただけでは変えない。ダイアログの下書き（localStorage）も、見出しのある古い形は同じく1行目にまとめて読む。新しいアイデアの見出しは常に空。
  - **済み（チェック）**: 実装したアイデア・没にしたアイデアを消し込む。削除（ゴミ箱）とは別。カードの左のチェックボックス（押せる所は 40px 四方。読み上げは「『…』を済みにする」／「『…』の済みを外す」）で済みにすると、斜線＋グレー（内容は2行まで。「続きを表示」で全部）になり、仕切りの下（「済み n件」の区切りの下）へ沈む。並びは、済みでないものが手で並べた順（`order`）、済みのものがその後ろに新しく済みにしたものから（`checkedAt` の新しい順。`sortIdeas`）。ホームの各仕切りとタイトルのアイデアタブで同じ。↑↓と「位置を選んで移動」は済みでないアイデアの中だけで動かし、済みのカードには↑↓を出さない。済みのアイデアを別の仕切りへ移す時は位置を選ばず、移動先でも済みのまま下にまとまる。済みを外すと済みでないものの末尾に戻る。カードが画面の外へ動いても消えた（削除した）ように見えないよう、済みにした・外した時は通知（「『…』を済みにしました（下の『済み』へ移しました）」／「『…』の済みを外しました（済みでないものの末尾へ戻しました）」。読み上げにも届く）で知らせ、移った先のカードを少しの間目立たせる（スクロールはしない）。済みにした・外した後は、空いた所に来たカード（同じ側の次、なければ前）のチェックボックスにフォーカスが移り、キーボードで続けて消し込める。同じ側にほかのカードがなければ、動いた先の自分のチェックボックスにフォーカスを残して見える所まで出す。
  - **データ**: `Idea.checked`（無い = 済みでない）と `Idea.checkedAt`（済みにした日時。済みでなければ null）。足しただけの項目なのでデータの形の版（DATA_MODEL）は上げない。修復は持たない古いアイデアに項目を足さない（足して書き戻すと、同期でほかの端末の「済み」を打ち消すため。壊れた値だけ直す）。同期では短い項目として項目ごとに合わせる（両方で変えていたら後から合わせた端末。内容 `body` は今までどおり両方の文章をつなぐ）。見出しも短い項目だが、この端末で見出しを内容の1行目にまとめて（空にして）保存した間に、別の端末（古い版）で見出しを直していたら、その見出しを残す（消えないように。内容と重なって見えるだけで、次に編集して保存すると内容へまとまる）。ゴミ箱から戻すと済みかどうかも元に戻り、済みでないアイデアは済みでないものの中の元の位置に戻る。古いバックアップもそのまま読み込める。
  - **件数**: 仕切りの見出し・仕切りの一覧・ホームの「アイデア」・タイトルカードの件数は、済みも含めたその場所のアイデアの数（済みも仕切りの中に残っているため）。済みの数は区切り「済み n件」と、仕切りの件数の読み上げ・ツールチップ（「うち済み n件」）で伝える。
  - **Claude**: コネクタの `novel_get_notes`（kind = ideas）はアプリと同じ並びで返し、済みには【済】を付ける（一覧の見出しに「うち済み n件」）。古い版の見出しがあればそのまま出す。
- **設定項目**: `SettingCategory`（任意に追加できる項目。既定はキャラクター・世界観）と `SettingEntry`（項目内の各エントリ。任意のフィールド＋本文）。項目ごとにフィールドのテンプレートを持てる。
- **戦略**: タイトルの全体方針メモ（`Title.strategyNote`）と、応募計画 `Submission` の並び（応募順）。各応募はコンテスト名・主催・URL・締切・応募日・結果発表日・状態・選考段階・概要・規定（文字数または400字詰め原稿用紙換算の枚数: `limitUnit`）・規定の備考（`limitNote`）・提出する梗概・あらすじとキャッチコピー（それぞれ文字数の規定つき）・特記事項（`specialNotes`）・結果・改稿方針・再応募方針、応募時点の採用原稿スナップショットを持つ（規定の備考からの4項目は後から足したもの。[SPEC-2.md](SPEC-2.md) の 9.）。スナップショットには話ごとの採用稿名・文字数・**本文の控え**・本文の指紋と、その時の梗概・あらすじ／キャッチコピーが入り、稿が後で編集・削除されても応募した原稿を読める・書き出せる。記録後の変化は本文の指紋で判定する（稿の名前やメモの変更は数えない）。
- **文字数**: 空白・改行を除いた文字数を基本とし、400字詰め原稿用紙換算も出す（`src/domain/text.ts`）。「採用原稿なし」は第n話と特殊ブロックを分けて数える（`missingActiveLabel`）。
- **保存**: 入力欄の下書きは最大 1.5 秒でストアへ反映し（応募計画の規定の文字数のように確定した時だけ保存する欄は、日本語入力の変換の途中で区切らないよう、Enter・フォーカスを外した時・画面を閉じる時に反映する）、ストアは最大 2 秒で IndexedDB に保存する。画面を閉じる・裏に回る時は下書きをすべて反映してから、未保存の変更を localStorage にタブごとの控えとして同期的に書き、次回起動時に読み込んだデータより新しいものだけを書き戻す（`src/store/lifecycle.ts`）。起動時とバックアップ復元時に参照切れなどの不整合を修復する（`src/domain/repair.ts`）。2.1 から原稿画面だけは保存ボタンで確定する（[SPEC-2.md](SPEC-2.md) の 5.）。
- **アプリの更新**: 執筆中に勝手に再読み込みしないよう、新しいバージョンは「更新する」を押した時に保存してから適用する。
- **起動アニメーション**（`src/launch/launch.js`）: 開いた時に、画面いっぱいにアニメーション「グリッチ」（約1.75秒）を出す。CRT が温まるように数本のレーザーが明滅し、色ずれと共に原稿用紙のマス目へ揃って「物語を、書く。」が灯り、マス目が一本の線に潰れて上下に開くと点の「Novel Studio」が現れ、最後に走査線が一度だけ通り抜ける。色は外観に合わせる（ホワイトは白地に赤、ダークは黒地に緑、ディープダークは黒地に暗い緑。「端末の設定に合わせる」は端末のライト／ダーク）。Web 版とアプリで同じ。
  - **出す時**: Web 版はウインドウ・タブを開いた最初の1回（`sessionStorage` の印。同じウインドウの再読み込みでは出さず、新しいタブ・インストールしたアプリの新しいウインドウでは出す）。見えていないタブ（裏で開いたタブ・先読み）で開いた時は出さず、そのタブが見えた時に出したことにする（後の再読み込みでも出さない）。アプリ（iPhone / Android）は起動のたび（裏から戻る時はページを読み込み直さないので出ない）。設定 → 表示 の「起動アニメーション」（オン／オフ。既定はオン。この端末だけの設定で、同期しない。`novel-studio:prefs` の `launchAnimation`）をオフにすると出さない。テスト（`navigator.webdriver`）では出さず、localStorage の `novel-studio:launch` を `force` にするか URL に `launch=1` を付けた時だけ出す（`e2e/launch.spec.ts`）。
  - **消える時**: アニメーションが終わり、アプリが最初の画面（読み込み中…ではなく、データを読み込んだ後の画面）を出せた（`src/main.tsx` が `NovelStudioLaunch.appReady()` を呼ぶ）の両方がそろったら、0.25秒で消えて取り除く（canvas・Worker も手放す）。画面を押す・キーを押すとすぐ消える（押した所の下の画面は押されない。指で押した時のクリックは指を離した後に作られるので、重なりを押したら、指・マウスを離して0.1秒たつまでは見えなくなった重なりを残してその操作の続き（離す・クリック・長押しのメニュー）を受け止め、それから取り除く。押したままでも消え始めて3秒で取り除く）。アプリが知らせてこなくても、出してから5秒で消える。端末の「視差効果を減らす」（`prefers-reduced-motion`）では動かさず、最後の絵（ロゴ）を、描いてから0.5秒ほど出して消える（数えるのはロゴを描いた時から。描く準備・Worker の立ち上がりに時間がかかる遅い端末でも、ロゴを0.5秒は出す）。重なりは読み上げず（`aria-hidden`）、フォーカスできるものを置かない。
  - **起動を遅くしない**: アプリの本体（JavaScript）の読み込みを待たず、読み込みも1つも増やさないよう、`src/launch/launch.js` を開発サーバーでもビルドでも `index.html` にそのまま埋め込む（`vite.config.ts` の `inlineLaunchScript`。ビルドでは縮める）。最初の描画の前に外観（`<html data-theme>` とブラウザの枠の色）を決めるのも同じスクリプト（起動後は `PrefsEffect` が同じ規則で反映する）。重なりは `<html>` の直下（`<body>` より前）に置き、地の色だけをその場で出す。描くのは HTML を読み終えた後で、ふだんは Worker（OffscreenCanvas。別のスレッド）が描くので、アプリの起動と取り合わず、アプリが重い処理をしている間も止まらない。Worker を使えない時（古い iOS など）はページの中で描く（下ごしらえは最初の描画の時）。絵はノッチ・ホームバーを除いた所の中央に置く。
  - アプリの起動の画面（スプラッシュ）はロゴの無い無地にし、アニメーションが地の色を出したらすぐ消す（[SPEC-2.md](SPEC-2.md) の 10.）。


### UI の約束事

- 画面は `<AppHeader crumbs={[...]} actions={...} />` ＋ `<main className="page">` で作る（原稿画面のような全面レイアウトは `page` を使わない）。
- 操作は `attempt(() => actions.xxx(...))` で呼ぶ（DomainError はトーストで表示される）。
- 削除などは `await confirmDialog({ title, message, danger: true, confirmLabel: '削除' })`、名前入力は `await promptDialog(...)`。
- テキスト入力は `DraftInput` / `DraftTextarea`（下書きを保持して遅延保存）。**別レコードを表示するときは `key={record.id}` を必ず付ける**。原稿画面（本文・稿の名前・推敲メモ・話の題・見出し）だけは `SessionTextarea` / `SessionInput`（`src/features/piece/SessionField.tsx`）で編集セッションに持ち、「保存」で確定する。
- データの読み取りは `const data = useData()` ＋ `useMemo(() => 導出(data, ...), [data, ...])`。セレクタで毎回新しい配列を返さない（無限再描画になる）。単一レコードは `useRecord('versions', id)`。
- 長編（数百話・数百万字）でも重くならないよう、原稿全体をなめる重い導出（文字数・枚数・指紋）は `bodyMetrics(version)`（稿ごとのキャッシュ）を使い、`useMemo` の依存は `data` 全体ではなく実際に使う表（`data.pieces`・`data.versions`・`data.chapters`・`title.structure` など）に絞る。一覧の行は `React.memo` でレコード単位の props にする（例: `src/features/title/story/useStoryData.ts`）。
- スタイルは `src/styles.css` の既存クラス（`btn`, `btn-primary`, `btn-active`, `btn-danger`, `btn-ghost`, `btn-sm`, `icon-btn`, `card`, `card-pad`, `section`, `section-head`, `list`, `empty`, `badge-*`, `tabs`, `segmented`, `switch`, `field`, `input`, `textarea`, `select`, `input-bare`, `row`, `stack`, `muted`, `small`, `hide-mobile`, `show-mobile`）と CSS 変数を使う。機能固有のスタイルは各機能ディレクトリの CSS ファイル（例: `src/features/piece/piece.css`）に書き、コンポーネントから import する。
- 色は `src/styles.css` の CSS 変数だけを使う（`#fff` などを直接書かない）。外観はホワイト／ダーク／ディープダークの3種（`<html data-theme>`）で、どの外観でも白い面が出ず読めること。領域ごとの色（本編・設定項目・戦略・アイデア・タイトル）は要素に `data-area="story"` などを付けると、その中で `--area`・`--area-text`・`--area-soft` として使える。
- 書体は UI が `--font-ui`（各端末の標準ゴシック）、原稿・題名・通し読みが `--editor-font`（設定で明朝に切り替え可）。
- 文言は日本語。スマホ（幅 360px〜）でも操作できること（ボタンは 34px 以上、横スクロールしない）。
- テスト用に主要な要素には `data-testid` を付ける。
