# Novel Studio 仕様書

小説執筆アプリ。PWA（React + TypeScript + Vite）として作り、デスクトップ・iOS・Android のブラウザ／ホーム画面アプリで動く。データは端末内の IndexedDB に保存する（サーバーなし）。

## 1. 要件（原文の要約）

1. **アイデアリスト**: タイトルごとにあらかじめ仕切られている。タイトルを増やすほど仕切りが増える。どのタイトルにも属さないスペースもある。
2. **タイトルごとの管理**: 以下はすべてタイトルの配下に属する。
3. **設定項目**: キャラクター・世界観など。項目そのものを後から任意に追加できる。
4. **章管理のオン/オフ**（大長編向け）: 章をフォルダにして、その中に話を入れ、話順に任意にソートできる。
5. **話数単位の原稿管理**（コピー機能あり）: 推敲のため1話に複数バージョンを持てる。採用するバージョンをアクティブにするボタンがある。アクティブにした採用原稿だけが上位の層（章・タイトル）に反映される。原稿の管理単位は必ず「第n話」。第n話の下に話の題を任意に付けられる。階層は タイトル → 章（大長編の場合）→ 第n話。
6. **戦略**: 執筆中・完了後に、どのコンテストにどの順番で応募するか、結果はどうだったか、それを踏まえた改稿方針、コンテストの概要を踏まえた再応募方針など、商業的なアプローチを戦略的に管理する。
7. **見え方**:
   - 起動するとアイデア領域とタイトル群が表示される。
   - タイトルに入ると、設定項目・章（有効時）・アクティブな話が話数順に表示される。
   - **（肝）** アクティブ化されている話を開くと原稿が表示され、その右側（デスクトップ）／下側（iOS/Android）に推敲バージョンの一覧が表示される。任意のバージョンを選ぶと、現在の採用原稿と選んだバージョンを同じウインドウ内で並べて比較できる。左右・上下の比率はスライドで変更できる。
8. **追加の種類**: タイトルから追加するときは必ず「メモ」「話数追加」「特殊追加」から選ぶ。
   - **メモ**: タイトル付きの付箋。タイトル内で表示優先度が最も低く、常に一番下に配置。
   - **話数追加**: 強制的にその時点の最新話が作られる（作成直後なら第1話、次は第2話…）。**第n話の表記は変更できない**。ソートはでき、ソート後は並び順どおりに話数が書き換わる。**途中の話数は削除できない**（例: 第1〜4話で第2・3話を消して空洞化はできない。第4話を第2話にソートして詰めてから旧2・3話を削除する）。話数順を変えずに、その話のすべての原稿を非アクティブにすることはできる。その場合、通し読みでは該当話に「採用原稿がありません。」と表示される。
   - **特殊追加**: 話数に属さないブロック（プロローグ・エピローグ等）。話数が固まった後からでも差し込める。第n話の部分を任意に編集できる。

## 2. 設計上の決定

- **話数は保存しない**。`Title.structure`（タイトル直下の並び）と `Chapter.pieceIds`（章内の並び）から常に導出する（`src/domain/structure.ts`）。これで「表記変更不可」「ソートで話数が書き換わる」を構造的に保証する。
- 話（`Piece`）は `kind: 'episode' | 'special'`。special は話数を消費せず、`label` を自由に編集できる。
- **削除ルール**: episode は採番スコープ内の最後の話だけ削除可能（`canDeletePiece`）。special はいつでも削除可能。
- **話数の振り方**（章が有効なときのみ選べる）: `continuous`（通し番号・既定）／`perChapter`（章ごとに第1話から）。章が無効なときは常に通し番号。
- **話数追加の位置**: 通し番号では必ず全体の最新話になる位置（最新話の直後）。章を指定した場合も、最新話より前の章には追加できない（`episodeTargets` が候補を返す）。章ごとモードでは指定章の最新話になる。話や章より後ろにあるタイトル直下の特殊ブロック（エピローグ・あとがき等）より前に入る。新しい章も同じ位置に入る。
- **章の有効化**: 初回は「第1章」を作り既存の話をすべて入れる（話数は変わらない）。無効化しても章構成は保持し、平坦に表示する。再度有効にすると元の章構成で表示される。
- **章の削除** = 章の解除。中の話は章があった位置に章の外として並ぶ（話は消さない）。
- **並べ替え**: 1つ上/下（`movePieceStep`）と、位置を選んで移動（`movePiece` + `insertOptions`）。章が有効なとき、章の先頭から上へ動かすと章の外へ出て、章の外から章の方向へ動かすとその章の端に入る。章が無効な間に隠れた章の境目をまたいで1つ動かした時は、各章の話数を保ったまま読む順だけ入れ替える（↑→↓で元に戻り、章をオンに戻しても構成が崩れない）。
- **推敲バージョン**: 作成時に「第1稿」が作られ採用中になる。「第n稿」は連番（削除しても番号は再利用しない）。複製すると `第n稿（第m稿を複製）`。採用は1つだけ、または採用なし。
- **メモ**: 本編とは別リストで、タイトル画面の一番下に表示。
- **アイデア**: `titleId = null` が「どのタイトルにも属さない」。タイトルを削除すると、そのアイデアは「どのタイトルにも属さない」へ移る。
- **設定項目**: `SettingCategory`（任意に追加できる項目。既定はキャラクター・世界観）と `SettingEntry`（項目内の各エントリ。任意のフィールド＋本文）。項目ごとにフィールドのテンプレートを持てる。
- **戦略**: タイトルの全体方針メモ（`Title.strategyNote`）と、応募計画 `Submission` の並び（応募順）。各応募はコンテスト名・主催・URL・締切・応募日・結果発表日・状態・選考段階・概要・規定（文字数または400字詰め原稿用紙換算の枚数: `limitUnit`）・結果・改稿方針・再応募方針、応募時点の採用原稿スナップショットを持つ。スナップショットには話ごとの採用稿名・文字数・**本文の控え**・本文の指紋が入り、稿が後で編集・削除されても応募した原稿を読める・書き出せる。記録後の変化は本文の指紋で判定する（稿の名前やメモの変更は数えない）。
- **文字数**: 空白・改行を除いた文字数を基本とし、400字詰め原稿用紙換算も出す（`src/domain/text.ts`）。「採用原稿なし」は第n話と特殊ブロックを分けて数える（`missingActiveLabel`）。
- **保存**: 入力欄の下書きは最大 1.5 秒でストアへ反映し、ストアは最大 2 秒で IndexedDB に保存する。画面を閉じる・裏に回る時は下書きをすべて反映してから、未保存の変更を localStorage にタブごとの控えとして同期的に書き、次回起動時に読み込んだデータより新しいものだけを書き戻す（`src/store/lifecycle.ts`）。起動時とバックアップ復元時に参照切れなどの不整合を修復する（`src/domain/repair.ts`）。
- **アプリの更新**: 執筆中に勝手に再読み込みしないよう、新しいバージョンは「更新する」を押した時に保存してから適用する。

## 3. コード構成

```
src/domain/      純粋なドメインロジック（テスト済み）。UI から直接は呼ばず store/actions 経由で使う
  types.ts         データ型
  structure.ts     本編の平坦化・話数・ラベル・削除可否（読み取り専用）
  storyOps.ts      本編の更新（話数追加・特殊追加・移動・章・推敲バージョン）
  entityOps.ts     タイトル・アイデア・メモ・設定項目・戦略の更新と一覧取得
  readthrough.ts   通し読み（採用原稿のみ）とテキスト書き出し
  diff.ts          推敲比較用の差分
  text.ts          文字数
  backup.ts        JSON バックアップ
src/db/          IndexedDB（Dexie）への保存
src/store/
  appStore.ts      useApp / useData / useRecord / commit / flushNow
  actions.ts       actions.xxx(...) — UI から呼ぶ操作。仕様違反は DomainError を投げる
  uiStore.ts       usePrefs（比率・分割方向など端末ごとの設定）、notify/notifyError、attempt()
src/ui/          共通部品（Layout/AppHeader/Breadcrumbs, Modal, dialogs, DraftField, SplitPane, icons, hooks, browser）
src/features/    画面
src/routes.ts    パス生成（HashRouter）
```

### UI の約束事

- 画面は `<AppHeader crumbs={[...]} actions={...} />` ＋ `<main className="page">` で作る（原稿画面のような全面レイアウトは `page` を使わない）。
- 操作は `attempt(() => actions.xxx(...))` で呼ぶ（DomainError はトーストで表示される）。
- 削除などは `await confirmDialog({ title, message, danger: true, confirmLabel: '削除' })`、名前入力は `await promptDialog(...)`。
- テキスト入力は `DraftInput` / `DraftTextarea`（下書きを保持して遅延保存）。**別レコードを表示するときは `key={record.id}` を必ず付ける**。
- データの読み取りは `const data = useData()` ＋ `useMemo(() => 導出(data, ...), [data, ...])`。セレクタで毎回新しい配列を返さない（無限再描画になる）。単一レコードは `useRecord('versions', id)`。
- 長編（数百話・数百万字）でも重くならないよう、原稿全体をなめる重い導出（文字数・枚数・指紋）は `bodyMetrics(version)`（稿ごとのキャッシュ）を使い、`useMemo` の依存は `data` 全体ではなく実際に使う表（`data.pieces`・`data.versions`・`data.chapters`・`title.structure` など）に絞る。一覧の行は `React.memo` でレコード単位の props にする（例: `src/features/title/story/useStoryData.ts`）。
- スタイルは `src/styles.css` の既存クラス（`btn`, `btn-primary`, `btn-active`, `btn-danger`, `btn-ghost`, `btn-sm`, `icon-btn`, `card`, `card-pad`, `section`, `section-head`, `list`, `empty`, `badge-*`, `tabs`, `segmented`, `switch`, `field`, `input`, `textarea`, `select`, `input-bare`, `row`, `stack`, `muted`, `small`, `hide-mobile`, `show-mobile`）と CSS 変数を使う。機能固有のスタイルは各機能ディレクトリの CSS ファイル（例: `src/features/piece/piece.css`）に書き、コンポーネントから import する。
- 色は `src/styles.css` の CSS 変数だけを使う（`#fff` などを直接書かない）。外観はホワイト／ダーク／ディープダークの3種（`<html data-theme>`）で、どの外観でも白い面が出ず読めること。領域ごとの色（本編・設定項目・戦略・アイデア・タイトル）は要素に `data-area="story"` などを付けると、その中で `--area`・`--area-text`・`--area-soft` として使える。
- 書体は UI が `--font-ui`（各端末の標準ゴシック）、原稿・題名・通し読みが `--editor-font`（設定で明朝に切り替え可）。
- 文言は日本語。スマホ（幅 360px〜）でも操作できること（ボタンは 34px 以上、横スクロールしない）。
- テスト用に主要な要素には `data-testid` を付ける。
